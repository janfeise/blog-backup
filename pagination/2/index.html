新一期需求通常会创建新的远程分支，此时需要在本地创建对应分支并与其关联

cmd 
// -------------------本地同步远程分支-------------------
git branch -a # 查看远程分支
git checkout -b dev-0.1.0 origin/dev-0.1.0 # 本地创建分支 0.1.0 并关联到远程分支

提交流程

提交前，先使用 stash 暂存本地修改，再拉取最新代码，最后恢复修改。即使发生冲突，本地修改和远程代码也会保留，便于后续处理

最近在读中国史，从中有感。

我国皇位继承制度从“公天下”走向“家天下”，又在漫长的历史演变中逐渐形成以嫡长子继承为核心的规则。其间经历了无数次争夺、冲突与制度调整，最终才获得了相对稳定的形态；其中嫡长子继承制的核心便是：

稳定，需减少主观性，增加程序性

历朝历代的皇位更迭，往往都会引发动荡，甚至酿成内乱。

早期的禅让制强调“贤者居之”，但“贤”本身就是一个主观性极强的标准。在尧、舜、禹所处的时代，部落林立，所有部落之主为天下共主。可“贤者居之”的问题在于：谁才是贤者？由谁来判断一个人是否贤能？某个部落认可的人，其他部落是否也会服从？若不认可，权力交接时是否会发生动乱，或者埋下动乱的种子？

不难发现一旦缺少明确、统一且可执行的继承规则，权力交接就容易陷入争议。

解决 LLM 长时间推理过程中用户切换页面导致无法感知任务完成的问题

2026-07-25 15:17:39
阅读时间约 6 分钟 · 字数 1037

实现长耗时异步任务完成后的全局通知机制，确保用户在<u>离开当前页面后</u>仍能及时获知任务执行结果。

在前端中调用耗时接口，如：llm api时，可能耗时较长，此时用户可能离开该页面，那么当接口完成时，如何通知用户？ 目标：

  • 耗时接口完成时通知用户
  • 不进行通知：当且仅当用户停留在当前页面时，不进行通知

注意：

  • 刷新页面时，通知仍有效，因此此时不能完全依赖pinia等状态管理库，pinia只能缓存，但是页面刷新时失效（甚至无需pinia）
  • 通知数据可能不止一个，看做为一个数组[1, 2, 3]，若用户停留在1页面只通知[2, 3]……

难点：

  • 全局通知
  • 不通知，用户停留在当前页面时无需通知，即使刷新后也无需通知——通过路由判断是否通知
  • SSE断线重连：当用户离开或刷新页面时，SSE连接断开，此时如何恢复
