稳定-减少主观性，增加程序性

最近在读中国史，从中有感。

我国皇位继承制度从“公天下”走向“家天下”，又在漫长的历史演变中逐渐形成以嫡长子继承为核心的规则。其间经历了无数次争夺、冲突与制度调整，最终才获得了相对稳定的形态；其中嫡长子继承制的核心便是：

稳定，需减少主观性，增加程序性

历朝历代的皇位更迭，往往都会引发动荡，甚至酿成内乱。

早期的禅让制强调“贤者居之”，但“贤”本身就是一个主观性极强的标准。在尧、舜、禹所处的时代，部落林立，所有部落之主为天下共主。可“贤者居之”的问题在于：谁才是贤者？由谁来判断一个人是否贤能？某个部落认可的人，其他部落是否也会服从？若不认可，权力交接时是否会发生动乱，或者埋下动乱的种子？

不难发现一旦缺少明确、统一且可执行的继承规则，权力交接就容易陷入争议。每个人都可以按照自己的立场解释“贤”，而这种解释又常常与现实利益相互纠缠。

解决 LLM 长时间推理过程中用户切换页面导致无法感知任务完成的问题

实现长耗时异步任务完成后的全局通知机制，确保用户在<u>离开当前页面后</u>仍能及时获知任务执行结果。

在前端中调用耗时接口，如：llm api时，可能耗时较长，此时用户可能离开该页面，那么当接口完成时，如何通知用户？
目标：

  • 耗时接口完成时通知用户
  • 不进行通知：当且仅当用户停留在当前页面时，不进行通知

注意：

  • 刷新页面时，通知仍有效，因此此时不能完全依赖pinia等状态管理库，pinia只能缓存，但是页面刷新时失效（甚至无需pinia）
  • 通知数据可能不止一个，看做为一个数组[1, 2, 3]，若用户停留在1页面只通知[2, 3]……

难点：

  • 全局通知
  • 不通知，用户停留在当前页面时无需通知，即使刷新后也无需通知——通过路由判断是否通知
  • SSE断线重连：当用户离开或刷新页面时，SSE连接断开，此时如何恢复

HTML语义化标签 a

为什么点击跳转应该优先使用 a 标签

在前端开发中，“点击跳转”是一个再常见不过的需求，但很多实现方式却悄悄破坏了浏览器本该提供的能力

浏览器原生能力不只是跳转

<a> 标签不仅仅是一个链接，它是浏览器原生可识别的导航元素，这意味着浏览器会自动为它提供一整套交互能力：

  • Ctrl / Cmd + 点击，在新标签页打开：<a href=‘https://tilex.world’>Tilex Blog</a>

  • 鼠标中键点击，在新标签页打开

  • 右键菜单，支持“在新标签页打开”“在新窗口打开”等操作

这些交互行为无需开发者编写，而是浏览器默认为<a>标签提供的

html 
<a href="/detail">进入详情</a>

只要写下这一行，所有能力都会自动生效

vue 自定义hooks

Vue 自定义 Hooks：让组件逻辑与 UI 解耦

在 Vue 开发中，一个组件通常由两部分组成：

  • UI：页面结构与展示
  • 状态与逻辑：数据管理、事件处理、生命周期逻辑等

当组件较为简单时，通常会将这两部分直接写在同一个组件中。但随着业务复杂度提升，会逐渐出现以下问题：

  • 组件代码越来越长
  • 状态逻辑难以维护
  • 多个组件存在重复逻辑
  • UI 与业务逻辑强耦合

此时，自定义 Hooks 便成为了一个非常重要的解决方案。

什么是 Vue 自定义 Hooks

Vue 自定义 Hooks 本质上是：

  • 将组件中的状态与逻辑抽离到独立函数中
  • 通过组合式 API 实现<u>逻辑复用</u>
  • UI 组件只负责展示
  • Hooks 负责<u>管理状态与行为</u>

这种模式本质上是一种“逻辑复用”和“职责拆分”的思想。
