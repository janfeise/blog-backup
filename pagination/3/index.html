为什么点击跳转应该优先使用 a 标签

在前端开发中，“点击跳转”是一个再常见不过的需求，但很多实现方式却悄悄破坏了浏览器本该提供的能力

浏览器原生能力不只是跳转

<a> 标签不仅仅是一个链接，它是浏览器原生可识别的导航元素，这意味着浏览器会自动为它提供一整套交互能力：

  • Ctrl / Cmd + 点击，在新标签页打开：<a href=‘https://tilex.world’>Tilex Blog</a>

  • 鼠标中键点击，在新标签页打开

  • 右键菜单，支持“在新标签页打开”“在新窗口打开”等操作

这些交互行为无需开发者编写，而是浏览器默认为<a>标签提供的

html 
<a href="/detail">进入详情</a>

只要写下这一行，所有能力都会自动生效

Vue 自定义 Hooks：让组件逻辑与 UI 解耦

在 Vue 开发中，一个组件通常由两部分组成：

  • UI：页面结构与展示
  • 状态与逻辑：数据管理、事件处理、生命周期逻辑等

当组件较为简单时，通常会将这两部分直接写在同一个组件中。但随着业务复杂度提升，会逐渐出现以下问题：

  • 组件代码越来越长
  • 状态逻辑难以维护
  • 多个组件存在重复逻辑
  • UI 与业务逻辑强耦合

此时，自定义 Hooks 便成为了一个非常重要的解决方案。

什么是 Vue 自定义 Hooks

Vue 自定义 Hooks 本质上是：

  • 将组件中的状态与逻辑抽离到独立函数中
  • 通过组合式 API 实现<u>逻辑复用</u>
  • UI 组件只负责展示
  • Hooks 负责<u>管理状态与行为</u>

这种模式本质上是一种“逻辑复用”和“职责拆分”的思想。

在日常开发中，使用 ant-vue 组件库的 a-form 表单组件时涉及到表单的校验与自定义校验的需求，在此做一个梳理

基础校验通过配置 rules 即可，例如：

JS

  password: [{ required: true, type: 'string', min: 8, max: 20, message: "请输入密码" }]
