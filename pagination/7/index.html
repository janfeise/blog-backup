用「守卫式 return」优化 if 判断的代码风格

一、常规写法的问题

在日常开发中，我们经常需要通过 if 判断某个条件是否成立，然后再执行代码。例如：

js 
function process(data) {
  if (check(data) === true) {
    console.log("数据符合条件，开始处理...");
    // 一系列复杂的逻辑
    doSomething(data);
    saveResult(data);
  }
}

这样写虽然没有问题，但随着逻辑增多，容易形成「缩进地狱」：

  • 每多一层判断，就多一层缩进。
  • 外围逻辑被包裹在条件里，阅读时不够直观。
