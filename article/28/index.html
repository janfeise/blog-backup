# TypeScript 从入门

在前端工程逐渐复杂的背景下，类型系统不再是可选项，而是提升代码质量与可维护性的关键工具

TypeScript 通过“类型”这一抽象层，将原本松散的 JavaScript 代码变得更加可控、可预测

# 类型系统的三种使用方式

TypeScript 的强类型能力主要体现在三种使用方式中，但它们的适用场景和推荐程度各不相同

# 类型推断

当你定义变量但未显式声明类型时，TypeScript 会自动推断类型

ts 
let str = "hello";
str = 123; // 报错

这种方式的优点是简洁，但缺点也很明显：不直观，且一旦推断完成，类型就被“锁死”，在复杂业务中容易出现隐式问题，因此不推荐在核心逻辑中依赖类型推断

# 类型声明

这是开发中最常用、也是最推荐的方式

ts 
let str: string;
str = "hello";
// str = 123; // 报错

通过显式声明类型，可以让代码意图更加清晰，也更利于团队协作与维护

# 类型断言

当数据来源复杂（例如接口返回、DOM 获取）时，TypeScript 可能无法准确推断类型，这时可以使用断言

ts 
const el = document.getElementById("app") as HTMLDivElement;
el.style.color = "red";

需要注意，断言本质是“告诉编译器相信你”，因此必须在确定类型安全的前提下使用，否则容易引入隐藏错误

# 常用类型详解

# 基本数据类型

ts 
let num: number = 10;
let str: string = "text";
let flag: boolean = true;

# 数组类型

TypeScript 支持两种定义方式

ts 
let arr1: number[] = [1, 2, 3];
let arr2: Array<number> = [1, 2, 3];

推荐使用第一种，更简洁直观

# 元组

元组可以限制数组中每个元素的类型和数量

ts 
let arr: [number, string, number?] = [1, "hello"];

适用于结构固定的数据，例如接口返回的特定格式

# 函数类型

函数可以约束参数类型和返回值类型

ts 
function sum(a: number, b: number): number {
  return a + b;
}

// 可选参数
function greet(name: string, age?: number) {
  console.log(name, age);
}

// 默认参数
function greet2(name: string = "guest") {
  console.log(name);
}

在实际开发中，函数类型的约束可以显著减少调用错误

# 自定义类型的进阶：从定义到使用

在实际开发中，类型不仅仅是“声明一下”，更重要的是参与业务逻辑，约束数据流动。相比零散的基础类型，自定义类型才是 TypeScript 真正发挥价值的地方

# interface：描述“对象长什么样”

interface 的核心作用是：约束对象结构

不仅仅是定义字段，更重要的是在业务中“规范数据”

ts 
interface User {
  id: number;
  name: string;
  age?: number;
}

# 实际使用场景：接口数据约束

ts 
interface User {
  id: number;
  name: string;
}

// 模拟接口返回
function getUser(): User {
  return {
    id: 1,
    name: "Tom"
  };
}

const user = getUser();

// 使用时有明确提示
console.log(user.name);

# 实际使用场景：组件 props（前端高频）

ts 
interface Props {
  title: string;
  count: number;
}

function render(props: Props) {
  console.log(props.title, props.count);
}

render({ title: "标题", count: 10 });

可以看到，interface 的重点不是“定义”，而是让数据在传递过程中始终符合预期结构

# type：更灵活的类型组合工具

type 的本质是：给任意类型起名字，并进行组合

ts 
type ID = number | string;
type Point = { x: number; y: number };

# 实际使用场景：联合类型

ts 
type ID = number | string;

function findUser(id: ID) {
  console.log("查找用户:", id);
}

findUser(1);
findUser("abc123");

# 实际使用场景：组合类型

ts 
type User = {
  name: string;
};

type Admin = User & {
  role: string;
};

const admin: Admin = {
  name: "Tom",
  role: "super"
};

type 更像“拼装工具”，适合处理复杂类型关系

# interface 和 type 的核心区别（用例理解）

与其死记概念，不如看实际开发中如何选择

# 场景一：定义对象结构（推荐 interface）

ts 
interface User {
  name: string;
}

interface Admin extends User {
  role: string;
}

为什么用 interface
因为它天然适合“继承”和“扩展”，语义更清晰

# 场景二：需要联合或复杂组合（必须用 type）

ts 
type Status = "success" | "error" | "loading";

function handle(status: Status) {
  console.log(status);
}

interface 无法直接表达这种“多种可能值”

# 场景三：类型复用 + 扩展（两者都可以）

ts 
// interface 写法
interface A {
  x: number;
}
interface B extends A {
  y: number;
}

// type 写法
type A1 = { x: number };
type B1 = A1 & { y: number };

简单理解：

  • interface：更像“定义一个类结构”
  • type：更像“拼接类型表达式”

# 泛型：让类型“动态起来”

前面的类型都是固定的，而泛型解决的是：<u>类型在使用时才确定</u>

# 什么是泛型（直接看效果）

ts 
function identity<T>(value: T): T {
  return value;
}

const a = identity(10);       // number
const b = identity("hello"); // string

同一个函数，适配多种类型

# 泛型在业务中的真实作用

# 场景一：接口返回数据封装

ts 
interface ResponseData<T> {
  code: number;
  data: T;
}

function fetchData<T>(data: T): ResponseData<T> {
  return {
    code: 200,
    data
  };
}

const res = fetchData({ name: "Tom" });

// 自动推导类型
console.log(res.data.name);

重点：接口返回什么类型，由调用者决定

# 场景二：工具函数复用

ts 
function getFirst<T>(arr: T[]): T {
  return arr[0];
}

const num = getFirst([1, 2, 3]);       // number
const str = getFirst(["a", "b", "c"]); // string

避免为每种类型写一套函数

# 场景三：约束泛型（进阶但常用）

ts 
function getLength<T extends { length: number }>(val: T) {
  return val.length;
}

getLength("hello");
getLength([1, 2, 3]);

说明：泛型不仅灵活，还可以加“规则”

# 为什么泛型不能被可选参数替代

这是很多初学者容易混淆的点

ts 
// 可选参数：解决有没有
function fn(a?: number) {}

// 泛型：解决是什么类型
function fn2<T>(a: T): T {
  return a;
}

更直观一点的对比：

ts 
// 错误思路：想用一个函数处理所有类型
function get(val?: number) {
  return val;
}

// 正确做法：用泛型
function get2<T>(val: T): T {
  return val;
}

可选参数无法表达“多类型复用”，而泛型正是为此而生

# 小结

  • interface：用于定义清晰的对象结构，适合接口数据和组件传参
  • type：用于组合类型、联合类型，适合复杂类型表达
  • 泛型：用于提升代码复用性，让类型随使用场景动态变化

当项目规模变大后，这三者往往是一起配合使用的，而不是互相替代
