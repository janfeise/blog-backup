Ant Design Vue 组件库 Cascader、TreeSelect 组件梳理

阅读时间约 30 分钟 · 字数 5812

Cascader 组件文档：https://antdv.com/components/cascader-cn#api

TreeSelect 组件文档：https://antdv.com/components/tree-select-cn#api

在后台系统中，常用的组件离不开 Cascader（级联组件）、TreeSelect（树形选择组件） 等组件，在此做一个梳理，梳理要点如下：

  • 组件的数据格式梳理
  • 后端接口所需的数据格式梳理

# Cascader 组件

参数 数据结构 说明
options [{ label, value, children[] }] 可选项数据源
v-model:value=“selectValue” [‘浙江’, ‘杭州’, ‘西湖’] 选中数据值，路径数组，逐层深入

Cascader（级联选择器）适用于严格层级关系的数据选择。

典型场景：

  • 省 → 市 → 区
  • 产品分类 → 子分类 → 商品
  • 部门 → 科室 → 岗位

用户必须按照层级逐步选择，最终得到一条完整路径。

# 数据源结构：Option

Cascader 通过 options 属性定义数据源。

js 
const options = [ 
  { 
    label: '浙江', 
    value: 'zhejiang', 
    children: [ 
      { 
        label: '杭州', 
        value: 'hangzhou', 
        children: [ 
          { 
            label: '西湖', 
            value: 'xihu' 
          } 
        ] 
      } 
    ] 
  } 
]

对应的数据结构：

ts 
interface Option { 
  value: string | number 
  label?: any 
  disabled?: boolean 
  children?: Option[] 
  isLeaf?: boolean 
}

组件使用方式：

vue 
<a-cascader 
  v-model:value="selectValue" 
  :options="options" 
/>

# 返回值结构：v-model:value=“selectValue”

与很多组件不同，Cascader 返回的并不是当前节点，而是完整路径

例如用户选择： 西湖

text 
浙江 
 └─ 杭州 
     └─ 西湖

返回结果：

js 
["zhejiang", "hangzhou", "xihu"]

这表示用户的完整选择路径

因此：

js 
selectValue.value

得到的是：

js 
["zhejiang", "hangzhou", "xihu"]

而不是：

js 
"xihu"

# 接口提交时的数据转换

实际业务中，后端往往只需要最终节点 ID

例如：

js 
["zhejiang", "hangzhou", "xihu"]

提交给接口时需要转换为：

js 
"xihu"

处理方式：

js 
const areaId = selectValue.at(-1)

或者：

js 
const areaId = selectValue[selectValue.length - 1]

# 多选场景

开启多选后：

vue 
<a-cascader 
  multiple 
  v-model:value="selectValue" 
/>

返回结果：

js 
[ 
  ["zhejiang", "hangzhou", "xihu"], 
  ["sichuan", "chengdu"] 
]

后端通常需要：

js 
["xihu", "chengdu"]

转换代码：

js 
const result = selectValue.map(item => item.at(-1))

输出：

js 
["xihu", "chengdu"]

# 详情页回显问题

这是 Cascader 最容易踩坑的地方。

假设接口返回：

js 
{ 
  areaId: "xihu" 
}

直接赋值：

js 
selectValue.value = ["xihu"]

无法正常回显

因为 Cascader 需要的是完整路径：

js 
[ 
  "zhejiang", 
  "hangzhou", 
  "xihu" 
]

因此需要根据叶子节点 ID 反向查找整条路径

例如：递归查找

js 
function findPath(tree, target) { 
  for (const item of tree) { 
    const path = [item.value] 

    if (item.value === target) { 
      return path 
    } 

    if (item.children) { 
      const childPath = findPath(item.children, target) 

      if (childPath) { 
        return [...path, ...childPath] 
      } 
    } 
  } 

  return null 
}

使用：

js 
const path = findPath(options, 'xihu') 

console.log(path)

输出：

js 
[ 
  'zhejiang', 
  'hangzhou', 
  'xihu' 
]

然后：

js 
selectValue.value = path

即可正常回显

# TreeSelect 组件

参数 数据结构 说明
treeData [{ label, value, children[] }] 可选项数据源
v-model:value=“treeSelect” [‘option1’, ‘option2’] 直接返回选中数据的 value

TreeSelect（树选择器）适用于树状结构选择

典型场景：

  • 菜单权限
  • 组织架构
  • 部门树
  • 分类树
  • 功能模块选择

相比 Cascader，它更关注节点本身，而不是完整路径。

# 数据源结构：treeData

TreeSelect 使用 treeData 作为数据源

js 
const treeData = [ 
  { 
    title: '浙江', 
    value: 'zhejiang', 
    children: [ 
      { 
        title: '杭州', 
        value: 'hangzhou', 
        children: [ 
          { 
            title: '西湖', 
            value: 'xihu' 
          } 
        ] 
      } 
    ] 
  } 
]

对应结构：

ts 
interface TreeNode { 
  value: string | number 
  title: string 
  children?: TreeNode[] 
}

组件使用：

vue 
<a-tree-select 
  v-model:value="treeSelect" 
  :tree-data="treeData" 
/>

# 返回值结构：v-model:value=“treeSelect”

TreeSelect 返回的是节点值本身。

例如选择：

text 
浙江 
 └─ 杭州 
     └─ 西湖

返回：

js 
"xihu"

多选时：

js 
[ 
  "xihu", 
  "hangzhou" 
]

不会像 Cascader 一样返回完整路径

因此处理逻辑更加简单

# 接口提交

TreeSelect 返回的数据通常就是后端需要的数据。

例如：

js 
[ 
  "xihu", 
  "hangzhou" 
]

可直接提交：

js 
await save({ 
  ids: treeSelect.value 
})

无需额外转换。

# 详情页回显

接口返回：

js 
{ 
  ids: [ 
    "xihu", 
    "hangzhou" 
  ] 
}

直接赋值即可：

js 
treeSelect.value = data.ids

无需递归查找路径。

这是 TreeSelect 使用体验优于 Cascader 的一个重要原因。

# Cascader 与 TreeSelect 对比

对比项 Cascader TreeSelect
数据展示 级联面板 树形结构
返回值 路径数组，层层深入 当前节点
回显复杂度 高 低
提交复杂度 需要转换 直接提交
层级表达能力 强 中
适用场景 行政区域、分类路径 权限树、组织架构
多选支持 支持 支持
接口适配成本 较高 较低

# 总结

虽然 Cascader 和 TreeSelect 都用于处理层级数据，但二者的设计理念完全不同

  • Cascader 关注的是"路径"，返回完整层级链路，因此在提交和回显时通常需要进行额外的数据转换
  • TreeSelect 关注的是"节点"，返回值就是当前选中的节点 ID，与后端接口的数据格式天然契合，开发成本相对更低

在实际项目中，如果后端最终只需要节点 ID，并且不关心完整路径，那么优先考虑 TreeSelect；如果业务需要明确表达层级归属关系，则更适合使用 Cascader
