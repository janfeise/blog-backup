# JavaScript 封装与函数抽离：从参数繁杂到优雅解耦

在项目开发中，函数抽离和代码封装是提升代码可维护性的重要手段。 但如果处理不当，抽离出来的函数可能会变得参数过多、依赖复杂、难以复用。 本文结合一个“自动登出计时器”的案例，带你看看抽离的优缺点，以及如何优化成更优雅的写法。

# 1. 背景：抽离计时器逻辑

原本，登出计时器的逻辑与 UI 更新、数据展示等混在同一函数中。 为了代码更清晰，我们将计时器相关逻辑抽离成了两个函数：

js 
/**
 * 启动登出计时器，5分钟内客户没有活动，则自动登出
 */
const startLogOutTimer = (
  displayTimeLable,
  time,
  containerApp,
  labelWelcome
) => {
  const timer = setInterval(() => {
    initTime(displayTimeLable, time);

    if (time === 0) {
      containerApp.style.opacity = 0;
      labelWelcome.textContent = "Log in to get started";
      clearInterval(timer);
    }

    time--;
  }, 1000);
  return timer;
};

/**
 * 初始化时间
 */
const initTime = (displayTimeLable, time) => {
  let min = `${Math.trunc(time / 60)}`.padStart(2, 0);
  let sec = `${time % 60}`.padStart(2, 0);
  displayTimeLable.textContent = `${min}:${sec}`;
};

调用时这样写：

js 
if (logOutTimer) clearInterval(logOutTimer);
logOutTimer = startLogOutTimer(labelTimer, time, containerApp, labelWelcome);

# 2. 优点

  1. 功能内聚
    • 计时器逻辑集中在 startLogOutTimer 中，方便维护。
    • initTime 单独封装，避免重复代码。
  2. 职责清晰
    • startLogOutTimer 只做倒计时和登出，不管数据渲染。
    • updateUI 专注于更新 UI。
  3. 可复用性
    • 如果有其他模块需要倒计时功能，可以直接使用这两个函数。

# 3. 问题与不足

虽然抽离后更清晰，但也引入了几个问题：

  1. 参数过多
    • 需要传 displayTimeLable, time, containerApp, labelWelcome 四个参数，且和 UI 强绑定。
    • 调用方必须按顺序传参，容易出错。
  2. 全局变量依赖
    • logOutTimer 在全局管理，但 startLogOutTimer 内部不负责清理外部的状态，增加耦合。
  3. 扩展性差
    • ==登出逻辑写死为“隐藏 UI + 重置欢迎信息”，如果想加个弹窗，需要修改源代码==。

# 4. 优化方案：配置对象 + 回调函数

为了减少参数传递的繁琐度，并提升灵活性，我们可以使用 配置对象 + 回调函数 的方式改写：

js 
const startLogOutTimer = ({ time, onTick, onTimeout }) => {
  let timer = setInterval(() => {
    onTick(time);

    if (time === 0) {
      clearInterval(timer);
      onTimeout?.();
    }

    time--;
  }, 1000);
  return timer;
};

调用时只需要告诉它：

  • 倒计时多久（time）
  • 每秒执行什么（onTick）
  • 时间到时做什么（onTimeout）
js 
logOutTimer = startLogOutTimer({
  time: 30,
  onTick: (time) => initTime(labelTimer, time),
  onTimeout: () => {
    containerApp.style.opacity = 0;
    labelWelcome.textContent = "Log in to get started";
  }
});

# 5. 优化后的好处

  1. 减少参数混乱
    • 不用每次都传一堆 DOM 节点，按顺序传参的负担消失。
  2. 与 UI 解耦
    • 计时器逻辑不依赖具体的 DOM 元素，可在 Node.js、React、Vue 等环境复用。
  3. 更易扩展
    • 想修改超时行为，只需要传不同的 onTimeout。
  4. 结构更清晰
    • 逻辑和视图分离，阅读体验更好。

# 6. 总结

函数抽离是好事，但抽离后的设计是否优雅，取决于：

  • 参数是否可控（过多会让调用方痛苦）
  • 是否降低耦合（UI 逻辑和核心逻辑应尽量分开）
  • 是否方便扩展（不要让调用方必须改源码才能变更逻辑）

记住这三个原则，你的 JavaScript 封装就能既简洁又强大。

# 个人感悟

感觉和Java的接口思想类似，不指定具体做什么，只做规范

即，计时器的功能只需明确：

  • 倒计时多久（time）
  • 每秒执行什么（onTick）
  • 时间到时做什么（onTimeout）

而，具体做什么由调用函数实现

js 
logOutTimer = startLogOutTimer({
  time: 30,
  onTick: (time) => initTime(labelTimer, time),
  onTimeout: () => {
    containerApp.style.opacity = 0;
    labelWelcome.textContent = "Log in to get started";
  }
});
