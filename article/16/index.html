# 分析

大文件切片上传时，如何判断该文件是否已经上传？因为已经上传了，表示数据库中已经存储了该文件，即秒传；但，如果没有上传则需要重新上传，而问题在于：

  • 如何判断文件是否已经上传

因此需要唯一标识符，使用 MD5 算法对文件进行哈希运算，获取哈希运算的结果，作为该文件的唯一标识符

# 数据库设计

数据库设计会采用 两张表 的模式：

  • 文件表

    字段名 类型 说明
    id bigint 主键
    file_md5 char(32) 文件唯一标识
    file_name varchar 文件原名
    file_size bigint 文件总大小
    content_type varchar 文件类型
    storage_path varchar 文件本地路径
    status tinyint 文件状态（0: 上传中, 1: 已完成）
    create_time datetime 创建时间
    update_time datetime 最后更新时间

  • 文件分片表

    字段名 类型 说明
    id bigint 主键
    file_id bigint 外键，关联文件元信息
    chunk_index int 分片序号
    chunk_path varchar 本地分片路径
    status tinyint 分片状态（0: 未上传, 1: 已上传）
    update_time datetime 最后更新时间

# sql代码

  • 文件表
sql 
CREATE TABLE file_info (
    id BIGINT NOT NULL AUTO_INCREMENT,
    file_md5 CHAR(32) NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    file_size BIGINT NOT NULL,
    content_type VARCHAR(100),
    storage_path VARCHAR(500),
    status TINYINT DEFAULT 0 COMMENT '文件状态（0: 未上传, 1: 已完成）',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY idx_file_md5 (file_md5)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文件信息表';
  • 文件切片表
sql 
CREATE TABLE file_chunk (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '分片记录主键',
    file_id BIGINT NOT NULL COMMENT '对应文件元信息表的文件 ID',
    chunk_index INT NOT NULL COMMENT '分片序号，保证顺序',
    chunk_path VARCHAR(500) NOT NULL COMMENT '分片在本地存储的路径',
    status TINYINT DEFAULT 0 COMMENT '分片上传状态：0 未上传，1 已上传',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '分片最后更新时间',
    PRIMARY KEY (id),
    KEY idx_file_chunk (file_id, chunk_index)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文件分片表';

# 思路解析

文件上传前：

  • 客户端先计算文件的 MD5（作为唯一标识）
  • 请求服务器检查 file_info 表中是否已有此 file_md5
    • 存在且 status=1 → 文件已上传完成，可直接返回成功
    • 存在但 status=0 → 文件正在上传，可获取已上传分片信息
    • 不存在 → 新建 file_info 记录，并初始化 file_chunk 表中每个分片的记录（status=0）

文件只上传部分：

文件合并：

  • 所有分片上传完成后，合并分片到 storage_path 指定的最终文件。
  • 合并完成后，将 file_info.status 更新为 1（已完成）。
  • 可清理 file_chunk 中的本地分片，或者保留备份。
