# 完整的缓存系统: 从数据缓存到缓存校验与更新

背景：在项目obsidian-to-memo中，使用 Map 缓存数据，但初始时只做了初次加载的数据缓存，当数据更新后，缓存并没有做相应的处理

完整的缓存系统应包含以下几个方面：

  • 数据缓存
  • 缓存校验
  • 缓存更新

只有三者完整协同，缓存系统才能真正稳定运行。

在项目 obsidian-to-memo 中，就曾遇到过这样的问题：

最开始使用 Map 对已读取的数据进行了缓存（将数据放置在内存中），避免重复读取磁盘文件，但随着功能迭代，一个问题逐渐暴露：

文件内容已经更新，但缓存中的数据仍然是旧数据。

最终导致：

  • 页面展示内容未更新
  • 新消息无法及时显示
  • 缓存与真实数据不一致

# 完整的缓存系统

html 
读取数据
   ↓
写入缓存
   ↓
下次访问
   ↓
校验缓存是否有效
   ↓
有效：直接使用缓存
失效：重新读取并更新缓存

数据缓存，较为简单，只需将数据放置在缓存中即可，但是缓存校验与更新却需额外关注，当数据更新时，缓存应该具备校验能力，判断数据是否发生了更改，若发生了更改需对缓存进行更新

缓存校验一般通过：mtime进行校验，mtime 是 “Modification Time”（修改时间）的缩写，它是元数据（metadata）中的一个关键时间戳，用于追踪内容最后一次被修改的时间

若mtime更改，则需要对缓存进行更新：删除失效的缓存，读取新的数据，并写入缓存，完整的流程如下：

text 
                    [ 访问数据 ]
                          │
              ┌───────────┴───────────┐
              │                       │
         是否存在缓存？                否
              │                       │
             是                   [ 磁盘读取 ]
              │                       │
       校验 mtime 是否一致             │
              │                       │
       ┌──────┴──────┐                │
       │             │                │
     一致          不一致              │
       │             │                │
  [ 返回缓存 ]  [ 删除旧缓存 ]         │
                     │                │
                [ 重新读取文件 ]       │
                     │                │
                [ 重新解析数据 ]       │
                     │                │
                [ 更新缓存 ] ──────────┘
                     │
                [ 返回最新数据 ]

# mtime 缓存校验方案

项目中的实现：

js 
let cached = window.messageCache.get(file.path)

if (cached && cached.mtime === file.stat.mtime) {
  console.log("缓存命中", file.path)
  return cached.messages
}

这里的逻辑非常重要：

text 
缓存存在
+
mtime一致
=
缓存有效

否则：

text 
缓存失效

# 缓存失效后的处理

当检测到：

text 
缓存存在，但 mtime 已变化

说明：

text 
文件内容已经被修改

此时必须：

  • 删除旧缓存
  • 重新读取文件
  • 重新解析数据
  • 写入新缓存
