# 思维导图

核心概念 关键点 说明
抽象 忽略细节，提取核心 找出需要的数据项（属性）和方法（行为），形成类的基本骨架
封装 数据与方法的隐藏 尽可能将属性和方法设置为私有，减少对全局空间的污染
继承 代码复用，结构优化 当两个类重合度较高时，可以抽取公共部分，子类继承父类，实现“不要重复自己”
多态 方法的重写与扩展 子类默认继承父类的方法，但子类与父类在本质上不同，必要时可重写方法以体现差异

# 一、抽象：提取核心，忽略细节

抽象就是在复杂事物中提取关键特征，忽略无关细节。

例如：

  • 学生类：属性包括姓名、学号、年级；方法包括学习、考试。
  • 老师类：属性包括姓名、工号、职称；方法包括授课、批改作业。

我们不需要关心“学生穿什么鞋子”“老师用什么牌子的粉笔”，因为它们与类的本质无关。

抽象的意义在于让我们快速搭建数据模型，避免陷入琐碎细节。

# 二、封装：保护数据与方法

封装就是将属性和方法封装在类中，并尽量隐藏实现细节，只暴露必要接口。

以 Python 为例：

python 
class Student:
    def __init__(self, name, score):
        self.__name = name       # 私有属性
        self.__score = score     # 私有属性
    
    def get_score(self):         # 公有方法
        return self.__score

    def set_score(self, score):
        if 0 <= score <= 100:
            self.__score = score
        else:
            raise ValueError("成绩必须在0到100之间")
  • __name 和 __score 是私有属性，只能通过 get_score 和 set_score 访问。
  • 封装可以防止外部随意修改数据，保证类的完整性和安全性。

# 三、继承：避免重复，优化结构

继承就是把公共部分提取到父类，子类复用这些功能并扩展特性。

python 
class Person:
    def __init__(self, name):
        self.name = name
    
    def introduce(self):
        print(f"大家好，我是{self.name}")

class Student(Person):
    def __init__(self, name, student_id):
        super().__init__(name)
        self.student_id = student_id
    
    def study(self):
        print(f"{self.name}正在学习")

class Teacher(Person):
    def __init__(self, name, title):
        super().__init__(name)
        self.title = title
    
    def teach(self):
        print(f"{self.name}正在授课")
  • Student 和 Teacher 不需要重复写 introduce 方法，因为它们继承自 Person。
  • 这是 Don’t Repeat Yourself (DRY) 原则的体现。

# 四、多态：灵活扩展，方法重写

多态是指子类可以重写父类方法，在相同调用下表现不同的行为。

python 
class Person:
    def speak(self):
        print("我是一名普通人")

class Student(Person):
    def speak(self):
        print("我是学生，我要学习")

class Teacher(Person):
    def speak(self):
        print("我是老师，我要授课")

调用示例：

python 
people = [Student(), Teacher(), Person()]
for p in people:
    p.speak()

输出结果：

text 
我是学生，我要学习
我是老师，我要授课
我是一名普通人

相同方法 speak()，不同对象表现不同，这就是多态的核心。

# OOP in JS

在 JavaScript 中，面向对象编程（OOP）既支持 基于类的写法（ES6 class），也支持 基于构造函数和原型的方式。下面将构造函数相关内容集中整理。

# 1️⃣ 构造函数（Constructor Functions）

构造函数是用来创建对象的函数，约定首字母大写，==配合 new 关键字使用==。

特性 构造函数 普通函数
命名约定 首字母大写 小写开头
调用方式 使用 new 直接调用
this 指向 指向新创建的对象（实例） 默认指向全局对象（严格模式下为 undefined）
返回值 默认返回新对象 返回函数执行结果或 undefined
原型机制 可通过 prototype 给实例共享方法 通常不用于实例共享方法

示例：

js 
// 构造函数
function Student(name, age) {
  this.name = name;
  this.age = age;
}

const s1 = new Student("李华", 18);
const s2 = new Student("王五", 20);

console.log(s1); // Student { name: "李华", age: 18 }
console.log(s2); // Student { name: "王五", age: 20 }

# 2️⃣ ==new 关键字发生的4步==

构造函数就是下面这个函数：

js 
// 构造函数
function Student(name, age) {
  this.name = name;
  this.age = age;
}
js 
const s1 = new Student("李华", 18);

执行 new Student("李华", 18) 时，JavaScript 会自动执行：

  1. 创建新的空对象 {} , 每个示例都会在内存空间开辟新的空对象， 不会重复。
  2. 将构造函数内部的 this 指向第一步所创建的空对象 {}， 并调用构造函数，完成赋值等。
  3. 链接原型：obj.__proto__ = Student.prototype。
  4. 自动返回新对象。

❗ 若是没有使用 new 关键字会发生什么？

new 关键字会绑定this指向为对象，若没有 new 关键字，则 this 指向谁？没有 new Student 就是一个普通函数，一个普通函数没有调用函数，其 this 指向 window，而不是实例化的对象

# 3️⃣ 构造函数里定义方法的缺陷

❌ 错误做法：

js 
function Person(name, age) {
  this.name = name;
  this.age = age;
    
  this.sayHi = function() {
    console.log(`Hi, I'm ${this.name}, ${this.age} years old.`);
  };
}

const p1 = new Person("Alice", 20);
const p2 = new Person("Bob", 25);

console.log(p1.sayHi === p2.sayHi); // false
  • 每次 new Person 都会生成新的方法 sayHi 副本，占用额外内存。
  • 方法逻辑通常是共享的，不需要每个实例都拷贝一份。

# 4️⃣ 原型共享方法

✅ 正确做法：把方法挂在 原型 上，实现共享。

js 
function Student(name, age) {
  this.name = name;
  this.age = age;
}

Student.prototype.sayHello = function() {
  console.log(`你好，我是${this.name}，今年${this.age}岁`);
};

const s1 = new Student("李华", 18);
const s2 = new Student("王五", 20);

s1.sayHello(); // 你好，我是李华，今年18岁
s2.sayHello(); // 你好，我是王五，今年20岁
  • 方法只存在一份内存。
  • 所有实例都可通过原型链访问。

# 5️⃣ prototype 与 proto

属性 所属对象 指向/作用
prototype 构造函数（类） ==一块共有空间==，存放共享方法和数据，是实例继承的来源
__proto__ 实例对象 ==指向构造函数的 prototype，用于继承==
  • 类拥有 prototype，实例没有。
  • 实例拥有 *proto*，指向类的 prototype。
  • prototype 是共享空间，proto 才是继承链指针。
  • proto 为实例所继承类的prototype

因此在理解prototype时：

  • Student.prototype表示类Student所定义的共享空间，里面存放了Student所需的methods和共有数据
  • Object.prototype表示Object所定义的共享空间，里面存放了Object所需的methods

示例：

js 
const arr = [1, 2, 3]; 
console.log(arr.__proto__ === Array.prototype) // true

因为arr是类Array的实例，所以 arr.__proto__ 为类Array的prototype，而prototype表示一块共有空间，里面存放了Array定义的methods

# 6️⃣ 原型链（Prototype Chain）

原型链是 JS 对象继承的核心机制：

  1. 对象访问属性或方法时，先查自身。
  2. 未找到则沿 proto 向上查找。
  3. 最终到 Object.prototype。
  4. 如果仍未找到，返回 undefined。

示例：

js 
function Student(name, age) {
  this.name = name;
  this.age = age;
}

Student.prototype.sayHello = function() {
  console.log(`你好，我是${this.name}`);
}

const s1 = new Student("李华", 18);
s1.sayHello(); // 你好，我是李华

console.log(s1.__proto__ === Student.prototype); // true

原型链层级示意：

text 
s1 (实例)
  │
  └─ __proto__ ──> Student.prototype
                      │
                      └─ __proto__ ──> Object.prototype
                                          │
                                          └─ __proto__ ──> null
  • 实例对象 通过 proto 指向构造函数 prototype。
  • 构造函数的 prototype 最终指向 Object.prototype。
  • Object.prototype.*proto* === null，原型链终点。

在js中，一切皆对象： Array._proto_ 为 Object.prototype

DOM元素的原型链

# 示例

1. 原型链与 DOM 树是两回事

在浏览器中，每个 DOM 元素（比如 <h1>）都是一个 JavaScript 对象，这个对象有自己的 原型链：

js 
h1
 └─ HTMLHeadingElement.prototype
      └─ HTMLElement.prototype
           └─ Element.prototype
                └─ Node.prototype
                     └─ EventTarget.prototype
                          └─ Object.prototype

这是 对象继承关系，决定了 h1 可以访问哪些属性和方法（如 h1.innerText、h1.appendChild()、h1.addEventListener() 等）。

而 DOM 树是 页面结构，是节点的父子关系：

html 
<body>
  <h1>Hello</h1>
</body>

这里的父子关系是 DOM 树结构的概念：

js 
body
 └─ h1

2. 两者的区别

特性 原型链 DOM 树
类型 JS 对象继承 页面节点父子结构
作用 决定对象能访问哪些属性和方法 决定页面布局和节点层级
示例 h1.appendChild 来自 Node.prototype body.contains(h1) 来自 DOM 层级

重点：

  • h1 的原型链和 DOM 树没有直接关系，它只是 JS 对象的继承体系。
  • DOM 树反映的是页面节点结构，JS 原型链反映的是对象可访问属性和方法。
  • 当然，DOM 树上的节点都是 JS 对象，所以可以通过原型链调用方法操作 DOM。

3. 小结

  • 原型链 = 对象继承结构，决定方法/属性
  • DOM 树 = 页面节点结构，决定父子关系
  • 他们是两条不同的链，虽然最终你操作 DOM 节点时，会用到原型链的方法，但概念上并不直接关联

# 小结

  • 构造函数 + prototype 实现方法共享和继承。
  • *proto* 指向继承来源。
  • 原型链：实例 → 构造函数 prototype → Object.prototype → null。

# ES6 Class 详解

# 1. 引言

在 ES6 之前，JavaScript 使用 构造函数（constructor function）+ prototype 来实现面向对象编程。虽然功能上可以满足需求，但语法较为繁琐，尤其在需要定义多个方法时，不得不反复书写 类名.prototype.方法名 = function() {}，可读性较差。

ES6 引入了 Class（类），它其实是一种语法糖，底层依旧是基于构造函数和原型机制实现的，但书写方式更加简洁直观，符合传统面向对象语言（如 Java、C++）的习惯。

# 2. 基本语法

ES6 中定义一个类的基本结构如下：

js 
class 类名 {
  constructor(参数) {
    // 构造器，用来初始化实例的属性
  }

  方法名1() {
    // 定义在 prototype 上的共享方法
  }

  方法名2() {
    // 继续定义其它方法
  }
}

// 示例
class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  sayHello() {
    console.log(`Hi, I am ${this.name}`);
  }
}

✅ 要点：

  • constructor：构造函数，实例化时自动调用，用来定义属性。
  • 其它方法：<u>会被自动挂载到类的 prototype 上，供所有实例共享</u>。

# 3. 与构造函数的对比

# 传统写法（ES5）

js 
// 下面这个函数就是构造函数
function Person(name, age) {
  this.name = name;
  this.age = age;
}

Person.prototype.sayHello = function () {
  console.log(`Hi, I am ${this.name}`);
};

# ES6 写法

js 
class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  sayHello() {
    console.log(`Hi, I am ${this.name}`);
  }
}

👉 可以看到：

  • 属性仍然定义在 constructor 中。
  • 方法直接写在类内部即可，不需要显式地绑定到 prototype。
  • 语法更加简洁，逻辑更清晰。

# 4. 底层原理

虽然 ES6 class 看起来像是新的语法结构，但其本质依然是：

  • constructor 相当于构造函数。
  • 类中定义的方法依旧挂载在 prototype 上。
  • 不会为每个实例单独创建方法副本，而是共享同一个 prototype 方法空间。

你可以通过验证来证明：

js 
const p1 = new Person("Alice", 20);
const p2 = new Person("Bob", 22);

console.log(p1.sayHello === p2.sayHello); // true，共享方法

说明 sayHello 并不是每个实例独立拥有的，而是挂载在 Person.prototype 上。

# 5. getter和setter

在 JavaScript 中，修改对象属性最直接的方式就是直接赋值：

js 
const obj = {
    name: 'js'
};

obj.name = '李华'; // 直接修改对象的属性
console.log(obj.name); // 李华

而 ES6 引入的 getter 和 setter，虽然本质上是方法，但在外部表现为==属性==访问和赋值：

js 
const obj = {
    name: 'js',
    
    // getter: 读取属性时触发
    get info() { 
        return this.name; 
    },
    
    // setter: 设置属性时触发
    set info(_name) { 
        this.name = _name; 
    }
};

console.log(obj.info); // js
obj.info = '李华';     // 使用 setter 修改
console.log(obj.info); // 李华

❌ 错误示例：

js 
obj.info("李华"); // TypeError: obj.info is not a function

原因：getter 和 setter 是==属性==，不是函数，所以不能像方法一样调用。

# 作用

  • 封装访问逻辑：可以在读取或修改属性时执行额外逻辑，如校验、格式化等。
  • 隐藏内部实现：对外暴露统一接口，对内部字段进行保护。

# 使用注意

在类中使用 setter 时，不要直接使用与属性同名的字段，否则会导致无限递归：

js 
class Person {
  constructor(name, age) {
    this.name = name; // 调用 setter，触发校验或其他逻辑
    this.age = age;
  }

  get name() {
    return this._name;
  }

  set name(value) {
    if (value.length < 2) {
      throw new Error('名字太短');
    }
    this._name = value; // 使用下划线存储内部字段，避免和 setter 冲突
  }
}

const p = new Person('李华', 18);
console.log(p.name); // 李华,p.name表示调用getter
p.name = 'A'; // 抛出错误：名字太短

⚠️ 约定：下划线 _ 前缀常用于内部属性，以避免和 getter/setter 冲突。

# 6. static

在 JavaScript 的类中，static 用于定义静态方法。静态方法有以下特点：

  1. 只能被类调用，实例无法调用。
  2. 不存放prototype，类所独有。
  3. 常用于工具函数或通用功能，<u>不依赖实例的属性</u>。

# 示例

js 
class Calculator {
  static add(a, b) {
    return a + b;
  }

  instanceMethod() {
    return '这是实例方法，放置在prototype';
  }
}

// 静态方法调用
console.log(Calculator.add(2, 3)); // 5

// 实例无法调用静态方法
const calc = new Calculator();
console.log(calc.add); // undefined，类所独有，实例无法调用
console.log(calc.instanceMethod()); // 这是实例方法，放置在prototype

# 生活中的例子

  • Array.from() → 只能通过 Array 类调用，实例无法使用：
js 
console.log(Array.from('abc')); // ['a','b','c']
  • Number.parseFloat() → 只能通过 Number 类调用：
js 
console.log(Number.parseFloat('3.14')); // 3.14

# 总结

  • 静态方法属于类，而不是实例。
  • 常用于工具函数、工厂方法或不依赖实例的功能。
  • 实例只能访问普通方法，类可以访问静态方法。

# 7. obj.create 精确控制原型链的创建

通过 obj.create 可指定原型， 即继承自哪里，原型一般是幕后默认链接上的，如：new关键字，会自动链接原型，而 obj.create 将原型摆到明面上，可以自定义，自己指定原型

在 JavaScript 中，Object.create() 方法为我们提供了一种独特而强大的对象创建方式。与使用字面量 {} 或 new Object() 不同，它允许我们在创建新对象时，就精确地指定其原型对象。

核心作用： Object.create(obj) 的核心作用是创建一个全新的空对象，并将这个新对象的内部 [[Prototype]]（即 __proto__ 属性）直接链接到您指定的 obj 上。

可以这样理解其内部机制：

javascript 
// prototype：一块共有空间
let person = {
  greet() {
    console.log('Hello!');
  }
};

// 使用 Object.create 创建新对象，其原型指向 person
let john = Object.create(person);

// 本质上，相当于完成了这样的链接：
// john.__proto__ = person;
// (注意：在实际代码中应避免直接操作 __proto__)

john.greet(); // 输出: "Hello!"

在上面的例子中，john 对象本身是空的，但它通过原型链“继承”了 person 的 greet 方法。

关键特性与用途：

  1. 纯净的原型继承： 这是实现原型式继承最直接、最纯粹的方式，无需通过构造函数。

  2. 创建无原型对象： 您可以传入 null 来创建一个完全没有原型的对象。

    javascript 
    let bareObject = Object.create(null);
console.log(bareObject.toString); // undefined
// 这个对象不继承任何属性和方法，比如 toString、hasOwnProperty 等

  3. 属性描述符： Object.create 的第二个参数允许您为新对象定义自身的属性，并精确控制其特性（如 enumerable, writable, configurable）。

    javascript 
    let john = Object.create(person, {
  name: {
    value: 'John',
    writable: true,
    enumerable: true
  }
});

与 new 关键字的对比：

  • new Constructor()：创建的新对象原型指向 Constructor.prototype，并且会执行 Constructor 函数来初始化对象。
  • Object.create(obj)：创建的新对象原型直接指向 obj，过程更简洁，不涉及函数执行。

总结： Object.create 是 JavaScript 原型系统中一个基础且强大的工具。它让我们能够以声明式的方式构建原型链，是实现高级设计模式（如工厂模式、纯净的对象池）和理解 JavaScript 真正面向对象能力的基石。当您需要精细控制对象与其原型的关系时，Object.create 是不可或缺的选择。

# 8. 总结

  • ES6 Class 是构造函数 + 原型的语法糖，底层机制没有改变。
  • constructor 用来初始化实例属性。
  • 类中的方法会自动挂载到 prototype，而不是实例本身。
  • 语法更清晰，符合传统面向对象语言的习惯，提高了代码的可读性与可维护性。

# js 中 类与类之间的继承

关键点：this 指向

类通常不是独立的，而是交织在一起的，如：Student class 是 Person Class 的子类…………等等

# 构造函数 实现类与类之间的继承

示例:

js 
const Person = function (name, age) {
    this.name = name;
    this.age = age;
}

const Student = function (name, age, schoolId) {
    console.log(this);
    Person.call(this, name, age); // 将 person 的this 指向 student
    this.schoolId = schoolId;
}

const s1 = new Student("李华", 18, '2025010101');

解释：

构造函数是一个普通的函数，但通过 new 关键字可创建对象

js 
// 构造函数就是一个普通函数
function Student(name, age) {
  this.name = name;
  this.age = age;
}

const s1 = new Student("李华", 18); // 通过 new 实例化对象

那么如何通过构造函数实现类与类之间的继承呢？—— this 指向问题

js 
const Person = function (name, age) {
    this.name = name;
    this.age = age;
}

const s1 = new Person("李华", 18); // new 关键字将 this 指向实例化的对象

Person 就是一个普通函数，若没有 new 关键字，普通函数调用时（非严格模式下），this 默认指向全局对象（浏览器中是 window，Node.js 中是 global）

即：

js 
Person("王五"， 20);

函数 Person("王五"， 20); 单独调用，没有使用 new 关键字时，this.name 会是 undefined。

因此通过构造函数实现类与类之间的继承需要：绑定 this 关键字—— call() 和 apply() 可实现

js 
const Person = function (name, age) {
    this.name = name;
    this.age = age;
}

const Student = function (name, age, schoolId) {
    Person(name, age); // 会报错，因为没有 new 关键字，Person的this指向window，而不是实例化的对象本身
    this.schoolId = schoolId;
}

const s1 = new Student("李华", 18, '2025010101');
js 
Person(name, age); // 会报错，因为没有 new 关键字，Person的this指向window，而不是实例化的对象本身

如何解决？

Person 的 this 应该指向谁？Student 的 this

js 
const Student = function (name, age, schoolId) {
    console.log(this);
    Person.call(this, name, age); // 将 person 的this 指向 student，所有 student 实例化的对象都可以使用 person 类
    this.schoolId = schoolId;
}

# 手动设置原型链——类与类的继承

##原理

前提紧要：

  1. 类才有 prototype，指的是一块共享空间，实例化的对象可以访问，即继承
  2. 实例的 __proto__ 指的是，该实例所继承类的 prototype ，即指向共享空间
  3. 在js中，属性 和 prototype 是分开的，需分别设置
js 
// 父类（构造函数 + 原型方法）
function Parent(name) {
  this.name = name;                // 属性，每个实例都有的属性
}

步骤：

  1. 属性绑定：子类获取父类的属性

    js 
    // 子类构造函数
function Child(name, age) {
  Parent.call(this, name);        // 【第一步】第一个参数：this，第二个参数：name；设置属性
  this.age = age;
}

    call的作用：将 Person 的this指向第一个参数，那么父类 Person 构造时 this.name = name 的 this 指向子类，子类可以创建该属性

  2. 继承：原型链

    js 
    Child.prototype = Object.create(Parent.prototype); // 【第二步】设置 prototype

    上面的代码中，为什么是 prototype 而不是类？因为原型链传递的是共享空间，而不是类，类是每个实例都拥有的，但共享空间只有一块儿

    Object.create 的作用是： 将左边的__proto__绑定到右边，返回一个空对象，且该空对象的 __proto__ 为传入的参数 Parent.prototype，那么此时

    js 
    Child.prototpe = {
    [[__proto__]] : Parent.prototype,
};

    请问此时，Child.prototype.__proto__ 等于什么？——Parent.prototype，就是一个简单的对象属性访问：

    js 
    const a = {
    name: '李华'
};

a.name; // 李华

    ⛔: 设置 Child.prototype = Object.create(...) 要在添加或保留 Child.prototype 上方法==之前==，因为create返回的是一个空对象，否则赋值会覆盖先前的方法；常见顺序是先赋值再添加子类特有方法。

  3. 修正：修正 constructor

    js 
    Child.prototype.constructor = Child; // 【第三步】

    使用create的后遗症，Object.create(Parent.prototype) 创建的对象本身没有自有的 constructor 属性（create返回准一个空对象），它会从 Parent.prototype 继承 constructor（通常指向 Parent）。因此，执行完 Child.prototype = Object.create(Parent.prototype) 后，Child.prototype.constructor 会指向 Parent，这不符合直觉（构造器引用应指回 Child）

# object.create 实现类的继承

无论是实例继承原型还是子类继承父类，都需要使用create

在js中，构造函数和ES6 class，将类分为两部分：属性 和 prototype；而 Object.create 属性和原型“不分家”，约定俗成使用 init 初始化构造属性

js 
init(name, age) {
    this.name = name;
    this.age = age;
    return this; // ✅ 通常会 return this 方便链式调用
}

Object.create设置原型链就简单了

父类：

js

const Person = {
  init(name, age) {
    this.name = name;
    this.age = age;
    return this; // ✅ 通常返回 this 方便链式调用
  },
  greet() {
    console.log(`👤 我是 ${this.name}，今年 ${this.age} 岁。`);
  }
};

子类：

js 
// 子类原型，继承自 Person
const Student = Object.create(Person); // create的作用：将左边 Student.__proto__ 链接到传入参数：Person，即 Student.__proto__ === Person

Student.init = function (name, age, schoolId) {
  // 调用父类的 init 初始化 name 和 age
  Person.init.call(this, name, age); // 将Person.init的this指向Student
  this.schoolId = schoolId;
  return this;
};

Student.study = function () {
  console.log(`📚 学号 ${this.schoolId} 的 ${this.name} 正在学习！`);
};

const s1 = Object.create(Student).init("李华", 18, "2025010101");

# 多态（Polymorphism）

在面向对象编程中，「多态」指的是同一个方法在不同对象上表现出不同的行为。在实现继承后，子类可以重写（override）父类的方法，从而实现方法的覆盖。

这是因为在 JavaScript 中，当调用一个方法时，解释器会按照「从当前对象开始，逐层向原型链（父类）上查找」的顺序来定位方法。如果子类和父类中存在同名方法，那么查找会优先找到子类中的方法，而不会再继续向上查找父类的方法。由此，就实现了方法的重写与多态行为。

✅ 示例：

javascript 
// 父类
class Animal {
  speak() {
    console.log("动物发出声音");
  }
}

// 子类
class Dog extends Animal {
  // 重写父类的方法
  speak() {
    console.log("狗在汪汪叫");
  }
}

// 另一个子类
class Cat extends Animal {
  // 同样重写父类的方法
  speak() {
    console.log("猫在喵喵叫");
  }
}

// 测试多态
const a = new Animal();
const d = new Dog();
const c = new Cat();

a.speak(); // 输出：动物发出声音
d.speak(); // 输出：狗在汪汪叫
c.speak(); // 输出：猫在喵喵叫

🔎 解释：

  • Dog 和 Cat 都继承自 Animal，但它们分别重写了 speak() 方法。
  • 当我们对不同对象调用同一个方法名 speak() 时，会自动调用各自子类中重写的方法，这就是多态的体现。
  • 如果子类没有重写该方法，则会向上查找到父类的实现。

💡 总结： 多态的本质是「同一个接口，不同的实现」。通过子类重写父类的方法，程序可以根据对象的实际类型自动调用对应的实现，从而提高代码的灵活性和可扩展性。
