# JavaScript 事件流（Event Flow）详解

在前端开发中，事件是交互的核心，而**事件流（Event Flow）**决定了浏览器如何处理用户触发的事件（例如点击、键盘输入、鼠移动等）。理解事件流，有助于我们更好地控制事件触发的顺序，避免"父子元素都触发事件"的困惑。

# 1. 事件流的三个阶段

JavaScript 的事件流分为三个阶段：

截图来源：https://juejin.cn/post/6854573221983813645

# （1）捕获阶段（Capturing Phase）

事件从 DOM 树的根节点（window/document） 开始，沿着树形结构 由外到内 逐层传递。

<u>如果</u>在监听时设置了捕获参数 true，则在这个阶段触发：

js 
element.addEventListener("click", handler, true); // 捕获阶段触发

# （2）目标阶段（Target Phase）

事件到达真正的目标元素（event.target）。

在目标元素上：

  • 先触发捕获阶段的监听器（如果注册过）
  • 再触发冒泡阶段的监听器（默认）

# （3）冒泡阶段（Bubbling Phase）

事件从目标元素开始，由内向外逐层往上传递，直到根节点。

默认情况下，事件监听是在冒泡阶段触发的：

js 
element.addEventListener("click", handler); // 默认是冒泡阶段，第三个参数为 false

# 总结

事件流顺序是：捕获（由外到内）→ 目标 → 冒泡（由内到外）

默认情况下，事件监听会在冒泡阶段执行。

# 2. 事件流示意图

下面的示意图能更直观地展示事件流：

text 
window / document
   ↓ 捕获
 <div id="parent">
   ↓ 捕获
   <button id="child">点击我</button>
   ↑ 冒泡
 </div>
↑ 冒泡
window / document

当点击按钮时：

  1. 事件先从 document 向下捕获到 button
  2. 到达目标 button
  3. 再从 button 向上冒泡到 document

如果在捕获阶段监听，就会在向下的过程中触发；如果在冒泡阶段监听（默认），就会在向上的过程中触发。

# 3. 实际例子演示

通过代码来直观感受事件流：

html 
<div id="parent" style="padding: 30px; background: lightblue;">
  父元素
  <button id="child">点击我</button>
</div>

<script>
  const parent = document.getElementById("parent");
  const child = document.getElementById("child");

  // 父元素冒泡阶段
  parent.addEventListener("click", () => {
    console.log("父元素：冒泡阶段");
  });

  // 父元素捕获阶段
  parent.addEventListener("click", () => {
    console.log("父元素：捕获阶段");
  }, true);

  // 子元素（目标阶段）
  child.addEventListener("click", () => {
    console.log("子元素：点击事件");
  });
</script>

# 点击按钮 child 的执行顺序：

  1. 父元素捕获阶段
  2. 子元素点击事件
  3. 父元素冒泡阶段

控制台输出：

text 
父元素：捕获阶段
子元素：点击事件
父元素：冒泡阶段

# 4. 为什么父子元素都会触发？

很多同学会疑惑：“我点击了子元素，为什么父元素也触发了？”

原因就在于事件会沿着 DOM 树传播：

  • 捕获阶段：由外到内，经过父元素，第三个参数设置为 true 可以将捕获阶段开启，因此先输出：父元素：捕获阶段
  • 目标阶段：到达子元素
  • 冒泡阶段：由内到外，再次经过父元素，触发父元素的监听事件，输出：父元素：冒泡阶段

因此，父子元素上的事件监听器都会被触发。理解这一点是掌握事件流的关键。

# 5. 阻止事件传播

如果不希望事件继续冒泡或捕获，可以使用：

js 
e.stopPropagation(); // 阻止事件继续传播

这在某些场景下非常有用，比如点击子元素时不想触发父元素的事件。

# ==事件委托（Event Delegation）==

# 什么是事件委托

事件委托的核心思想是：将子元素的事件交给父元素处理。

利用事件冒泡机制，我们只需在父元素上注册一个事件监听器，就能捕获所有子元素的事件，从而避免对每个子元素逐一绑定监听。

事件委托的两个关键点：

  1. 子元素拥有同一个父元素
  2. 通过 e.target 找到真正触发事件的子元素

这样可以显著提高性能，尤其在有大量相似子元素时（如导航栏菜单、表格行、列表项等）。

# 为什么要用事件委托

  • 性能优化：减少事件监听器的数量，降低内存开销
  • 动态元素支持：后续添加的新子元素也会被自动监听，无需额外绑定
  • 代码简洁：只需在父元素上绑定一次，逻辑更清晰

# 案例一：导航栏链接smooth跳转

该案例由单页面组成，点击导航栏可以跳转到页面的不同位置，使用事件委托实现：平滑滚动到对应的页面区域，因为默认的跳转是直接跳转，而不是平滑跳转

HTML 结构：

html 
<nav class="nav">
  <ul class="nav__links">
    <li class="nav__item">
      <a class="nav__link" href="#section--1">Features</a>
    </li>
    <li class="nav__item">
      <a class="nav__link" href="#section--2">Operations</a>
    </li>
    <li class="nav__item">
      <a class="nav__link" href="#section--3">Testimonials</a>
    </li>
    <li class="nav__item">
      <a class="nav__link nav__link--btn btn--show-modal" href="#">
        Open account
      </a>
    </li>
  </ul>
</nav>

JavaScript 代码：

js 
// 1. 获取父元素
const navLinks = document.querySelector('.nav__links');

// 2. 给父元素注册事件监听
navLinks.addEventListener('click', function (e) {
  /**
   * 找到需要的子元素
   * 控制台输出可能是：
   *  <a class="nav__link" href="#section__1">Operations</a>  【需要的子元素】
   *  <ul class="nav__links">...</ul>                         【干扰元素】
   */
  console.log(e.target);
    
  // 3. 判断实际点击的元素
  if (e.target.classList.contains('nav__link')) {
    e.preventDefault(); // 阻止默认跳转
    const id = e.target.getAttribute('href'); // 获取跳转目标
    document.querySelector(id).scrollIntoView({ behavior: 'smooth' }); // 平滑跳转
  }
});

# 代码解析

  1. 父元素监听：事件统一绑定在 .nav__links 上
  2. 事件目标识别：通过 e.target 获取点击的子元素
  3. 条件过滤：使用 classList.contains('nav__link') 确保点击的是需要的链接，而不是其他元素
  4. 实现效果：平滑滚动到对应的页面区域

# 案例二：选项卡切换

点击不同的button，显示不同的内容

选项卡（Tabs）切换是前端开发中非常常见的功能。我们不需要为每个按钮都绑定监听器，而是可以通过事件委托的方式，只在父容器上注册一次事件，就能完成所有按钮的切换逻辑。

# HTML 结构

html 
<div class="operations">
  <!-- 按钮容器 -->
  <div class="operations__tab-container">
    <button class="btn operations__tab operations__tab--1 operations__tab--active" data-tab="1">
      <span>01</span>Instant Transfers
    </button>
    <button class="btn operations__tab operations__tab--2" data-tab="2">
      <span>02</span>Instant Loans
    </button>
    <button class="btn operations__tab operations__tab--3" data-tab="3">
      <span>03</span>Instant Closing
    </button>
  </div>

  <!-- 内容区域 -->
  <div class="operations__content operations__content--1 operations__content--active">内容1</div>
  <div class="operations__content operations__content--2">内容2</div>
  <div class="operations__content operations__content--3">内容3</div>
</div>

# JavaScript 代码实现

核心思路：

  • 使用事件委托，只在父容器 .operations__tab-container 上绑定一次 click 事件
  • 使用 e.target.closest('button') 来确保点击到按钮或内部子元素（如 <span>）都能正确定位到按钮
  • 使用 dataset.tab 来动态切换对应的内容
js 
const tabsContainer = document.querySelector('.operations__tab-container');
const tabs = document.querySelectorAll('.operations__tab');
const tabsContent = document.querySelectorAll('.operations__content');

// 事件委托：监听父容器
tabsContainer.addEventListener('click', function (e) {
  const clicked = e.target.closest('button'); // 找到点击的按钮

  // Guard Clause：如果点到的不是按钮，直接返回
  if (!clicked) return;

  // 1. 移除所有按钮的 active 样式
  tabs.forEach(t => t.classList.remove('operations__tab--active'));

  // 2. 为当前按钮添加 active 样式
  clicked.classList.add('operations__tab--active');

  // 3. 隐藏所有内容区域
  tabsContent.forEach(c => c.classList.remove('operations__content--active'));

  // 4. 显示对应的内容（根据 data-tab 匹配）
  document
    .querySelector(`.operations__content--${clicked.dataset.tab}`)
    .classList.add('operations__content--active');
});

# 关键点解析

  1. 事件委托（Event Delegation）
    • 不需要给每个按钮都注册事件，只需在父容器上绑定一次即可
    • 借助事件流的冒泡机制，点击子元素时事件会冒泡到父容器
  2. closest 的使用
    • e.target.closest('button') 会向上查找最近的 <button> 元素
    • 即使点击的是按钮内部的 <span>，也能找到父级 <button>，避免选择不到正确元素
  3. Guard Clause（守卫语句）
    • 如果点击的是空白区域或容器内部的非按钮元素，直接 return，代码更健壮
  4. 利用 data 属性切换内容
    • data-tab="1" 对应 .operations__content--1
    • 这样实现按钮和内容的动态绑定，扩展性很强

# 案例三：导航菜单悬停效果

在导航菜单中，我们常常需要实现鼠标悬停时，<u>当前链接高亮</u>，<u>其他链接变淡的效果</u>。通过事件委托配合 closest() 和 querySelectorAll()，可以高效实现这一功能。

# 为什么使用 closest() 配合 querySelectorAll()

在事件委托中，我们需要：

  1. 定位当前操作的元素：使用 e.target 获取触发事件的元素
  2. 查找所有相关的兄弟元素：需要一个方法找到所有需要操作的同级元素，这样才能将其它链接变淡

这时组合使用 closest() 和 querySelectorAll() 就非常巧妙：

  • closest('.nav')：向上查找最近的 .nav 父容器
  • .querySelectorAll('.nav__link')：在该父容器内查找所有 .nav__link 子元素

这样做的好处是：

  • 无需预先用变量保存所有链接元素
  • 即使 DOM 结构动态变化，也能准确找到所有相关元素
  • 代码逻辑更清晰，维护性更好

# JavaScript 代码实现

js 
const nav = document.querySelector('.nav');

function handleHover(e) {
  const target = e.target;

  // Guard Clause：只处理导航链接
  if (!target.classList.contains("nav__link")) return;

  // 通过 closest 找到父容器，再用 querySelectorAll 获取所有链接
  const links = target.closest(".nav").querySelectorAll(".nav__link");
  
  // 遍历所有链接，改变非当前链接的透明度
  links.forEach((link) => {
    if (link !== target) {
      link.style.opacity = this; // this 为传入的透明度值
    }
  });
}

// 鼠标移入时，其他链接变淡
nav.addEventListener("mouseover", handleHover.bind(0.5));

// 鼠标移出时，所有链接恢复
nav.addEventListener("mouseout", handleHover.bind(1));

# 代码解析

  1. 事件委托：在 .nav 父元素上监听 mouseover 和 mouseout 事件
  2. Guard Clause：通过 classList.contains("nav__link") 确保只处理导航链接，忽略其他元素（如 logo、按钮等）
  3. closest() + querySelectorAll() 组合：
    • target.closest(".nav")：从当前元素向上查找最近的 .nav 容器
    • .querySelectorAll(".nav__link")：在该容器内查找所有导航链接
    • 这样就获得了所有需要操作的兄弟元素
  4. 使用 bind 传递参数：
    • handleHover.bind(0.5)：鼠标悬停时，其他链接透明度设为 0.5
    • handleHover.bind(1)：鼠标移出时，所有链接透明度恢复为 1
  5. 性能优势：
    • 只绑定一次事件监听器，而不是为每个链接单独绑定
    • 即使后续动态添加新的导航链接，也无需额外处理

# 总结

事件流是前端开发中的核心概念，理解事件流的三个阶段（捕获、目标、冒泡）能帮助我们更好地控制交互逻辑。

事件委托是基于事件流的重要应用技巧，它的核心是：

  • 父元素监听 + 子元素定位（e.target）
  • 利用冒泡机制，减少事件监听器数量，提升性能
  • 配合 closest() 和 querySelectorAll() 可以灵活处理复杂的 DOM 操作

事件委托特别适用于：

  • 菜单导航
  • 表格操作按钮
  • 动态生成的列表项
  • 大量相似元素的交互

掌握事件流和事件委托，能让我们写出更高效、更易维护的前端代码。
