# MySQL 执行顺序

视频：数据库面试——SQL执行顺序_哔哩哔哩_bilibili

MySQL执行顺序与编写顺序不同，编写顺序：

sql 
select

from

where

group by

having

order by

limit

编写顺序从上到下依次编写，但执行顺序却不同：中间开始，返回头部，最后执行尾部

sql 
1. FROM
   确定数据来源，从指定表中获取数据

2. WHERE
   对原始数据进行筛选，只保留满足条件的数据行

3. GROUP BY
   对筛选后的数据进行分组

4. HAVING
   对分组后的结果再次进行筛选，通常用于筛选聚合结果

5. SELECT
   决定最终需要返回哪些字段、表达式或聚合结果

6. ORDER BY
   对查询结果进行排序

7. LIMIT
   限制最终返回的数据条数

因此，默认情况下，select 语句设置的别名，只有尾部 order by 才能使用（limit 只是限制数量，不做筛选），但 MySQL 对 having、order by 做了优化，having 与 order by 也可以使用 select 设置的别名，示例：

sql 
SELECT
    class_name,
    AVG(score) AS avg_score
FROM score
GROUP BY class_name
HAVING avg_score > 83;

执行顺序是：

  • from
  • group by
  • having
  • select

此时 select 设置的别名，having 等语句访问应该是无效的，但由于 MySQL 做了优化，上面的代码也可以正确运行

# 正则

REGEXP 是 Regular Expression（正则表达式）的缩写

REGEXP 是用于进行正则表达式匹配的运算符，用于检查一个字符串是否匹配指定的正则表达式模式，示例：

查找 name 字段中以 ‘st’ 为开头的所有数据：

sql 
SELECT name 
FROM person_tbl 
WHERE name REGEXP '^st';
分类 语法 / 符号 示例 说明
正则查询 REGEXP WHERE name REGEXP 'Tom' 判断字段是否匹配正则表达式
RLIKE WHERE name RLIKE 'Tom' REGEXP 的同义写法
REGEXP_LIKE() WHERE REGEXP_LIKE(name, 'Tom') MySQL 8.0 推荐的正则函数写法
位置匹配 ^ WHERE name REGEXP '^Tom' 匹配以 Tom 开头的字符串
$ WHERE name REGEXP 'Tom$' 匹配以 Tom 结尾的字符串
任意字符 . WHERE name REGEXP 'T.m' . 表示任意单个字符，如 Tom、Tim
重复匹配 * WHERE name REGEXP 'ab*c' 前一个字符出现 0 次或多次
+ WHERE name REGEXP 'ab+c' 前一个字符出现 1 次或多次
? WHERE name REGEXP 'ab?c' 前一个字符出现 0 次或 1 次
次数匹配 {n} WHERE code REGEXP '[0-9]{4}' 前一个模式恰好出现 n 次
{n,} WHERE code REGEXP '[0-9]{4,}' 至少出现 n 次
{n,m} WHERE code REGEXP '[0-9]{2,4}' 出现 n 到 m 次
字符集合 [abc] WHERE name REGEXP '[abc]' 匹配 a、b、c 中任意一个字符
[a-z] WHERE name REGEXP '[a-z]' 匹配指定字符范围
[0-9] WHERE code REGEXP '[0-9]' 匹配数字

多条件 ` ` `WHERE name REGEXP 'Tom

数字 [[:digit:]] WHERE code REGEXP '[[:digit:]]' 匹配数字字符
字母 [[:alpha:]] WHERE name REGEXP '[[:alpha:]]' 匹配字母
字母数字 [[:alnum:]] WHERE code REGEXP '[[:alnum:]]' 匹配字母或数字
空白字符 [[:space:]] WHERE content REGEXP '[[:space:]]' 匹配空格、换行等空白字符

# 分组

聚合函数 作用 示例
GROUP BY 分组 SELECT class_name FROM score GROUP BY class_name;
HAVING 如果要过滤的不是原始数据，而是分组之后的结果，就要使用 HAVING SELECT class_name, AVG(score) AS avg_score FROM score GROUP BY class_name HAVING AVG(score) > 83;

HAVING 示例：查询平均分大于 83 的班级

id student_name class_name gender score
1 Tom A 男 80
2 Jack A 男 90
3 Lucy A 女 85
4 Jerry B 男 70
5 Alice B 女 95

如果要过滤的不是原始数据，而是分组之后的结果，就要使用 HAVING

思路：

  1. 对班级进行分组，分为A班和B班
  2. 计算每个班级的平均分，A班的平均分，B班的平均分
  3. 筛选平均分大于83的班级

由于是对分组后的结果进行处理，需使用 having

sql 
SELECT
    class_name,
    AVG(score) AS avg_score
FROM score
GROUP BY class_name
HAVING avg_score > 83;

# 多表查询

笛卡尔积：《离散数学》知识点详解：集合的运算（笛卡尔积）_哔哩哔哩_bilibili

SQL关系代数：【关系代数】并、交、差与广义笛卡尔积_哔哩哔哩_bilibili

当一个查询需要同时使用多张表中的数据时，就属于多表查询，理解多表查询，可以先从 笛卡尔积 开始：

假设有两张表：

# S 学生表

Sno Sname
001 Tom
002 Jack

# SC 成绩表

Sno Course Score
001 MySQL 90
001 Java 85
002 MySQL 80

如果直接查询两张表：

sql 
SELECT S.*, SC.*
FROM S, SC;

没有设置任何关联条件，此时会得到两张表的 笛卡尔积

如果：

text 
S 表有 m 行
SC 表有 n 行

那么理论上会得到：

text 
m × n 行

因为 S 表中的每一行都会分别与 SC 表中的每一行进行组合

例如：

text 
S.001 × SC.001 MySQL
S.001 × SC.001 Java
S.001 × SC.002 MySQL

S.002 × SC.001 MySQL
S.002 × SC.001 Java
S.002 × SC.002 MySQL

总共：

text 
2 × 3 = 6 行

将两张表进行笛卡尔积，得到的是第一张表每行数据与另一张表所有数据合并的结果，如上图所示，S表的006数据与SC表的每行数据进行合并，得到了5行数据，总共20行数据，后续的多表查询便是再次基础上进行处理，而且实际业务中，我们通常并不需要所有组合，而只需要存在关系的数据，如学生编号相同时才认为两条数据有关联：

  1. 多表进行笛卡尔积

    sql 
    select S.*, SC.*
from S, SC;

    便能得到上图中的20行大表，后续对这张大表进行业务处理即可（看作一张表）

  2. 后续业务处理，如：学生编号相同

    sql 
    select S.*, SC.*
from S, SC
where S.Sno = SC.Sno;

这种写法属于较早的隐式连接写法，实际开发中更推荐明确使用 JOIN

sql 
SELECT S.*, SC.*
FROM S
INNER JOIN SC
    ON S.Sno = SC.Sno;

这两种写法在这里表达的查询含义基本相同：

sql 
FROM S, SC
WHERE S.Sno = SC.Sno

等价理解为：

sql 
FROM S
INNER JOIN SC
ON S.Sno = SC.Sno

需要注意：

“先生成完整笛卡尔积，再使用 WHERE 筛选”适合作为理解模型

但 MySQL 实际执行查询时，优化器通常不会真的先生成一张巨大的笛卡尔积临时表，再进行筛选，而会选择更高效的连接算法和执行计划

# 连接 JOIN

MYSQL面试——left join 、inner join 、right join区别_哔哩哔哩_bilibili

JOIN 用于：根据连接条件，将多张表中满足条件的行组合成新的结果集

例如：

sql 
S.Sno = SC.Sno

就是一个连接条件

常见 JOIN 包括：

类型 含义
CROSS JOIN 所有行互相组合，即笛卡尔积
INNER JOIN 只保留满足连接条件的数据
LEFT JOIN 保留左表全部数据，同时连接右表匹配的数据
RIGHT JOIN 保留右表全部数据，同时连接左表匹配的数据

维恩图：

# CROSS JOIN

CROSS JOIN 就是笛卡尔积

sql 
SELECT *
FROM S
CROSS JOIN SC;

如果：

text 
S：4 行
SC：5 行

结果：

text 
4 × 5 = 20 行

因此：

sql 
FROM S, SC

可以理解为一种隐式的 CROSS JOIN

# 左连接

左连接的核心规则是：

左表全部保留，右表能匹配就连接，左表不能匹配项填 NULL

将 from Student 的 Student 作为左表，left join SC 的 SC 作为右表，两者进行左连接

sql 
from A（左表）
LEFT JOIN B（右表）

# 内连接 INNER JOIN

内连接：左表公共部分与右表公共部分做笛卡尔积，核心规则是：

满足连接条件的行组合

示例：

sql 
SELECT
    S.Sno,
    S.Sname,
    SC.Course,
    SC.Score
FROM S
INNER JOIN SC
    ON S.Sno = SC.Sno;

执行逻辑可以理解为：

text 
S 表
  │
  │ S.Sno = SC.Sno
  ▼
寻找 SC 表中满足条件的数据
  │
  ▼
组合匹配成功的数据

例如：

text 
S

001 Tom
002 Jack
003 Lucy
SC

001 MySQL 90
001 Java 85
002 MySQL 80
004 Java 90

执行：

sql 
SELECT *
FROM S
INNER JOIN SC
    ON S.Sno = SC.Sno;

得到：

text 
001 Tom  001 MySQL 90
001 Tom  001 Java  85
002 Jack 002 MySQL 80

其中：

text 
003 Lucy
004 Java

不会出现在最终结果中，因为它们没有找到满足连接条件的数据

# ON 与 WHERE

学习 JOIN 时，还需要区分：

sql 
ON

与：

sql 
WHERE

ON 主要用于描述：

两张表之间如何进行匹配

例如：

sql 
ON S.Sno = SC.Sno

WHERE 主要用于描述：

对连接完成后的结果进一步进行筛选

例如查询 MySQL 成绩大于 80 分的学生：

sql 
SELECT
    S.Sname,
    SC.Score
FROM S
INNER JOIN SC
    ON S.Sno = SC.Sno
WHERE SC.Course = 'MySQL'
  AND SC.Score > 80;

可以理解为：

text 
S
        \
         \ S.Sno = SC.Sno
          JOIN
         /
SC
        ↓
   得到关联数据
        ↓
WHERE Course = 'MySQL'
  AND Score > 80
        ↓
   得到最终结果

因此可以简单记忆：

text 
ON      → 表与表怎么关联
WHERE   → 结果还需要满足什么条件

需要注意，对于外连接 LEFT JOIN / RIGHT JOIN，将条件写在 ON 还是 WHERE 中可能直接改变查询结果，因此两者不能认为完全等价

# 多表查询整体理解

整个知识点可以整理成一条主线：

text 
多表查询
│
├── CROSS JOIN
│     └── 所有数据组合：笛卡尔积
│
├── INNER JOIN
│     └── 只保留匹配成功的数据
│
├── LEFT JOIN
│     └── 左表全部保留
│         ├── 匹配成功 → 合并右表数据
│         └── 匹配失败 → 右表字段 NULL
│
└── RIGHT JOIN
      └── 右表全部保留
          ├── 匹配成功 → 合并左表数据
          └── 匹配失败 → 左表字段 NULL

最核心的理解是：

text 
JOIN ≠ 单纯寻找两个集合的交集

JOIN = 根据 ON 条件寻找行与行之间的匹配关系，并将匹配的数据组合起来

其中：

text 
INNER JOIN → 只要匹配成功的数据

LEFT JOIN  → 左边全部要，右边能匹配多少就匹配多少

RIGHT JOIN → 右边全部要，左边能匹配多少就匹配多少

CROSS JOIN → 不考虑匹配关系，所有数据互相组合
