# 一、前置准备

在开始之前，请确保你的开发环境已安装以下工具：

  • JDK 21：Java 开发工具包
  • Maven：项目依赖管理工具
  • Navicat：数据库可视化管理工具（或其他 MySQL 客户端）
  • IntelliJ IDEA：集成开发环境（推荐）

# 三、整合 MyBatis

# 3.1 什么是 MyBatis？

MyBatis 是用来在 Java 程序中方便地执行 SQL 的持久层框架。

它的核心作用：

  • 将 Java 对象和数据库表进行映射
  • 避免编写大量的 JDBC 样板代码
  • 通过 XML 或注解方式管理 SQL 语句

# 3.2 添加 MyBatis 依赖

编辑 pom.xml 文件，在 <dependencies> 标签中添加：

文件位置：项目根目录/pom.xml

xml 
<dependencies>
    <!-- MyBatis Spring Boot Starter -->
    <dependency>
        <groupId>org.mybatis.spring.boot</groupId>
        <artifactId>mybatis-spring-boot-starter</artifactId>
        <version>3.0.3</version>
    </dependency>
    
    <!-- 其它必要依赖 -->
    
    <!-- Spring Boot Web -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <!-- MySQL 驱动 -->
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <scope>runtime</scope>
    </dependency>

    <!-- Spring Boot DevTools -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-devtools</artifactId>
        <scope>runtime</scope>
        <optional>true</optional>
    </dependency>

    <!-- Spring Boot Test -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

版本兼容说明：

  • Spring Boot 3.5.6 推荐使用 MyBatis Starter 3.0.3 或以上

添加依赖后，点击 IDEA 右上角的 Maven 刷新按钮（或按 Ctrl + Shift + O）下载依赖。

# 四、数据库准备

# 4.1 创建数据库

  1. 打开 Navicat，连接到本地 MySQL 服务（通常是 localhost）

# 五、配置 MyBatis 和数据源

编辑 application.properties 配置文件。

文件位置：src/main/resources/application.properties

properties 
# 应用名称
spring.application.name=tilex-blog-backend

# ========== 数据源配置 ==========
# MySQL 8.x 驱动
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
# 数据库连接 URL（替换【数据库名】和时区）
spring.datasource.url=jdbc:mysql://localhost:3306/【数据库名】?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai
# 数据库用户名
spring.datasource.username=root
# 数据库密码（替换为你的实际密码）
spring.datasource.password=123456

# ========== MyBatis 配置 ==========
# 指定 Mapper XML 文件的位置
mybatis.mapper-locations=classpath:mappers/*.xml
# 指定实体类的包路径，用于类型别名（在 XML 中可以直接使用类名）
mybatis.type-aliases-package=blog.tilex.backend.tilex_blog_backend.entity
# 开启驼峰命名自动映射（doc_id -> docId）
mybatis.configuration.map-underscore-to-camel-case=true
# 打印 SQL 日志（开发时可选，便于调试）
mybatis.configuration.log-impl=org.apache.ibatis.logging.stdout.StdOutImpl

配置说明：

配置项 作用
spring.datasource.url 指定数据库连接地址，包含数据库名和连接参数
mybatis.mapper-locations 告诉 MyBatis 去哪里找 SQL 映射文件（XML）
mybatis.type-aliases-package 配置实体类的包路径，在 XML 中可以简写类名
map-underscore-to-camel-case 自动将数据库下划线命名转为 Java 驼峰命名
log-impl 开启 SQL 日志输出，便于开发调试

# 六、编写代码实现数据访问

# 6.1 创建实体类（Entity）

实体类的作用：<u>对应数据库表的结构</u>，定义字段和类型。

文件位置：src/main/java/blog/tilex/backend/tilex_blog_backend/entity/Doc.java

java 
package blog.tilex.backend.tilex_blog_backend.entity;

import java.sql.Timestamp;

/**
 * 文档实体类
 * 对应数据库表：doc
 */
public class Doc {
    private Long docId;          // 文档ID
    private String title;        // 标题
    private String content;      // 内容
    private String author;       // 作者
    private Timestamp createdAt; // 创建时间
    private Timestamp updatedAt; // 更新时间

    // 无参构造函数
    public Doc() {}

    // 全参构造函数
    public Doc(Long docId, String title, String content, String author, 
               Timestamp createdAt, Timestamp updatedAt) {
        this.docId = docId;
        this.title = title;
        this.content = content;
        this.author = author;
        this.createdAt = createdAt;
        this.updatedAt = updatedAt;
    }

    // Getter 和 Setter 方法
    public Long getDocId() {
        return docId;
    }

    public void setDocId(Long docId) {
        this.docId = docId;
    }

    public String getTitle() {
        return title;
    }

    public void setTitle(String title) {
        this.title = title;
    }

    public String getContent() {
        return content;
    }

    public void setContent(String content) {
        this.content = content;
    }

    public String getAuthor() {
        return author;
    }

    public void setAuthor(String author) {
        this.author = author;
    }

    public Timestamp getCreatedAt() {
        return createdAt;
    }

    public void setCreatedAt(Timestamp createdAt) {
        this.createdAt = createdAt;
    }

    public Timestamp getUpdatedAt() {
        return updatedAt;
    }

    public void setUpdatedAt(Timestamp updatedAt) {
        this.updatedAt = updatedAt;
    }

    // toString 方法，便于调试输出
    @Override
    public String toString() {
        return "Doc{" +
                "docId=" + docId +
                ", title='" + title + '\'' +
                ", content='" + content + '\'' +
                ", author='" + author + '\'' +
                ", createdAt=" + createdAt +
                ", updatedAt=" + updatedAt +
                '}';
    }
}

# 6.2 创建 Dao 接口

Dao（Data Access Object）的作用：定义数据访问方法的接口，声明对数据库的操作。

文件位置：src/main/java/blog/tilex/backend/tilex_blog_backend/dao/DocDao.java

java 
package blog.tilex.backend.tilex_blog_backend.dao;

import blog.tilex.backend.tilex_blog_backend.entity.Doc;
import org.apache.ibatis.annotations.Mapper;

import java.util.List;

/**
 * 文档 Dao 接口
 * 使用 @Mapper 注解标记为 MyBatis Mapper
 */
@Mapper
public interface DocDao {
    /**
     * 根据 ID 查询文档
     * @param docId 文档ID
     * @return 文档对象
     */
    Doc getDocById(Long docId);

    /**
     * 查询所有文档
     * @return 文档列表
     */
    List<Doc> getAllDocs();

    /**
     * 插入文档
     * @param doc 文档对象
     * @return 受影响的行数
     */
    int insertDoc(Doc doc);

    /**
     * 更新文档
     * @param doc 文档对象
     * @return 受影响的行数
     */
    int updateDoc(Doc doc);

    /**
     * 删除文档
     * @param docId 文档ID
     * @return 受影响的行数
     */
    int deleteDoc(Long docId);
}

注意事项：

  • 必须使用 @Mapper 注解或在启动类配置 @MapperScan
  • 接口方法的命名应清晰表达意图
  • 参数和返回值类型要与 Mapper XML 一致

# 6.3 创建 Mapper XML 文件

Mapper XML 的作用：编写具体的 SQL 语句，实现 Dao 接口中定义的方法。

文件位置：src/main/resources/mappers/DocMapper.xml

xml 
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" 
    "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<!-- namespace 必须是 Dao 接口的全限定名 -->
<mapper namespace="blog.tilex.backend.tilex_blog_backend.dao.DocDao">

    <!-- ResultMap：定义结果映射（可选，开启驼峰映射时可省略） -->
    <resultMap id="DocResultMap" type="Doc">
        <id property="docId" column="doc_id"/>
        <result property="title" column="title"/>
        <result property="content" column="content"/>
        <result property="author" column="author"/>
        <result property="createdAt" column="created_at"/>
        <result property="updatedAt" column="updated_at"/>
    </resultMap>

    <!-- 根据 ID 查询文档 -->
    <select id="getDocById" resultType="Doc" parameterType="long">
        SELECT * FROM doc WHERE doc_id = #{docId}
    </select>

    <!-- 查询所有文档 -->
    <select id="getAllDocs" resultType="Doc">
        SELECT * FROM doc ORDER BY created_at DESC
    </select>

    <!-- 插入文档 -->
    <insert id="insertDoc" parameterType="Doc" useGeneratedKeys="true" keyProperty="docId">
        INSERT INTO doc (title, content, author)
        VALUES (#{title}, #{content}, #{author})
    </insert>

    <!-- 更新文档 -->
    <update id="updateDoc" parameterType="Doc">
        UPDATE doc
        SET title = #{title},
            content = #{content},
            author = #{author}
        WHERE doc_id = #{docId}
    </update>

    <!-- 删除文档 -->
    <delete id="deleteDoc" parameterType="long">
        DELETE FROM doc WHERE doc_id = #{docId}
    </delete>

</mapper>

XML 配置说明：

标签/属性 说明
namespace 绑定 Dao 接口的全限定名，必须完全匹配
id 对应接口中的方法名
resultType 返回类型，因为配置了类型别名，可以简写为 Doc
parameterType 参数类型
#{property} MyBatis 参数占位符，会自动进行类型转换和预编译
useGeneratedKeys 插入时返回自增主键
keyProperty 指定主键对应的属性名

# 七、配置 Mapper 扫描

有两种方式配置 Mapper 扫描：

# 方式一：在启动类添加 @MapperScan 注解（推荐）

文件位置：src/main/java/blog/tilex/backend/tilex_blog_backend/TilexBlogBackendApplication.java

java 
package blog.tilex.backend.tilex_blog_backend;

import org.mybatis.spring.annotation.MapperScan;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
@MapperScan("blog.tilex.backend.tilex_blog_backend.dao")  // 扫描 Dao 包
public class TilexBlogBackendApplication {
    public static void main(String[] args) {
        SpringApplication.run(TilexBlogBackendApplication.class, args);
    }
}

# 方式二：在每个 Dao 接口上添加 @Mapper 注解

如果 Dao 接口不多，可以在每个接口上添加 @Mapper 注解（已在上面的 DocDao.java 中添加）。

推荐使用方式一，统一管理更方便。

# 十、常见问题与解决方案

# 10.1 包路径不存在错误

错误信息：

text 
java: 程序包 blog.tilex.entity 不存在

原因分析：

  • 实体类的包路径与配置不一致
  • Dao 接口中引用了错误的包路径
  • application.properties 中的类型别名包配置错误

解决方案：

  1. 检查实体类的 package 声明是否正确
  2. 统一所有包路径命名（建议使用小写，如 dao 而非 Dao）
  3. 确保 mybatis.type-aliases-package 配置正确
  4. 在 Dao 接口中使用完整的类路径或正确导入
java 
// 正确示例
package blog.tilex.backend.tilex_blog_backend.dao;
import blog.tilex.backend.tilex_blog_backend.entity.Doc;

@Mapper
public interface DocDao {
    Doc getDocById(Long docId);
}

# 10.2 Mapper XML 找不到

错误信息：

text 
Invalid bound statement (not found): blog.tilex.backend.tilex_blog_backend.dao.DocDao.getDocById

原因分析：

  • Mapper XML 文件位置不正确
  • namespace 与 Dao 接口全限定名不匹配
  • XML 中的 id 与接口方法名不匹配
  • Maven 打包时未包含 XML 文件

解决方案：

  1. 确认 XML 文件位置：src/main/resources/mappers/DocMapper.xml
  2. 检查 namespace 是否正确：
xml 
<!-- 必须与 Dao 接口的包名 + 类名完全一致 -->
<mapper namespace="blog.tilex.backend.tilex_blog_backend.dao.DocDao">
  1. 检查方法 id 是否匹配：
xml 
<!-- id 必须与接口方法名一致 -->
<select id="getDocById" resultType="Doc" parameterType="long">
    SELECT * FROM doc WHERE doc_id = #{docId}
</select>
  1. 在 pom.xml 中添加资源过滤配置（如果 XML 在 Java 目录下）：
xml 
<build>
    <resources>
        <resource>
            <directory>src/main/resources</directory>
            <includes>
                <include>**/*.xml</include>
                <include>**/*.properties</include>
            </includes>
        </resource>
    </resources>
</build>

错误信息：

原因分析：

# 确认用户名密码正确
spring.datasource.username=root
spring.datasource.password=你的实际密码
  1. 在 Navicat 中测试连接是否成功
  2. 确认数据库已创建：
sql 
SHOW DATABASES LIKE 'tilex_blog';

# 10.4 驼峰命名映射不生效

问题描述： 数据库字段 doc_id 无法映射到 Java 属性 docId，查询结果中该字段为 null。

原因分析：

  • 未开启驼峰命名映射配置
  • 字段名与属性名完全不匹配

解决方案：

  1. 确认已开启驼峰映射：
properties 
mybatis.configuration.map-underscore-to-camel-case=true
  1. 或使用 resultMap 手动映射：
xml 
<resultMap id="DocResultMap" type="Doc">
    <id property="docId" column="doc_id"/>
    <result property="title" column="title"/>
    <result property="createdAt" column="created_at"/>
</resultMap>

<select id="getDocById" resultMap="DocResultMap" parameterType="long">
    SELECT * FROM doc WHERE doc_id = #{docId}
</select>

# 10.7 参数传递错误

错误信息：

text 
BindingException: Parameter 'docId' not found

原因分析：

  • 接口方法参数未使用 @Param 注解
  • XML 中的参数名与接口不匹配

解决方案：

方式一：使用 @Param 注解（推荐多参数情况）：

java

方式三：传递对象：

# 10.8 Mapper XML 配置路径问题

问题描述： 不同项目结构可能需要不同的 Mapper 路径配置。

常见配置方式：

properties 
# 单层目录：mappers/*.xml

mybatis.mapper-locations=classpath:mappers/*.xml,classpath:mappers/user/*.xml,classpath:mappers/admin/*.xml

目录结构示例：

└── mappers/
    ├── user/

    │   └── UserRoleMapper.xml
    └── admin/
        └── AdminMapper.xml

# 10.9 事务管理问题

问题描述： 数据插入或更新后未生效，或部分操作需要回滚。

解决方案：

  1. Spring Boot 已自动配置事务管理，在 Service 层添加 @Transactional：
java 
package blog.tilex.backend.tilex_blog_backend.service.impl;

import blog.tilex.backend.tilex_blog_backend.dao.DocDao;
import blog.tilex.backend.tilex_blog_backend.entity.Doc;
import blog.tilex.backend.tilex_blog_backend.service.DocService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class DocServiceImpl implements DocService {
    
    @Autowired
    private DocDao docDao;
    
    @Override
    @Transactional  // 添加事务管理
    public void batchInsertDocs(List<Doc> docs) {
        for (Doc doc : docs) {
            docDao.insertDoc(doc);
        }
        // 如果中间出现异常，所有插入操作都会回滚
    }
}
  1. 确保数据库引擎支持事务（InnoDB）：
sql 
-- 查看表引擎
SHOW TABLE STATUS WHERE Name = 'doc';

-- 如果是 MyISAM，需要转换为 InnoDB
ALTER TABLE doc ENGINE=InnoDB;

# 10.10 中文乱码问题

问题描述： 插入或查询中文数据时出现乱码（??? 或其他字符）。

解决方案：

  1. 确保数据库、表、字段都使用 utf8mb4：
sql 
-- 查看数据库字符集
SHOW CREATE DATABASE tilex_blog;

-- 修改数据库字符集
ALTER DATABASE tilex_blog CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- 修改表字符集
ALTER TABLE doc CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
  1. 确保连接 URL 包含编码参数：
properties 
spring.datasource.url=jdbc:mysql://localhost:3306/tilex_blog?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai
  1. 确保 IDEA 和项目文件编码为 UTF-8：
    • File → Settings → Editor → File Encodings
    • 将所有编码设置为 UTF-8

# 十一、扩展建议

# 11.1 分层架构最佳实践

在实际项目中，建议采用完整的分层架构：

text 
controller (控制层) 
    ↓
service (业务层) 
    ↓
dao (数据访问层) 
    ↓
database (数据库)

示例代码结构：

java 
// Controller 层
@RestController
@RequestMapping("/api/doc")
public class DocController {
    @Autowired
    private DocService docService;
    
    @GetMapping("/{id}")
    public Doc getDoc(@PathVariable Long id) {
        return docService.getDocById(id);
    }
}

// Service 层
@Service
public class DocServiceImpl implements DocService {
    @Autowired
    private DocDao docDao;
    
    @Override
    public Doc getDocById(Long id) {
        // 可以在这里添加业务逻辑
        return docDao.getDocById(id);
    }
}

// Dao 层
@Mapper
public interface DocDao {
    Doc getDocById(Long id);
}
