# this 是什么？

在 JavaScript 中，this 是一个特殊的关键字，用于<u>在运行时动态绑定上下文</u>。 它的指向规则取决于函数的调用方式，而不是定义方式。

# 对象中的 this 指向问题

js 
/** 
* 定义一个对象，包含数据和函数
* 这里并没有闭包，因为对象并不是 scope
* 在对象中定义的函数，谁调用就指向谁
*/
const obj = {
  name: "小明",
  age: 20,
  sayInfo: function() {
    console.log("普通调用 ->", this.name, this.age); 
  }
};

obj.sayInfo();  
// this 指向 obj，输出: 普通调用 -> 小明 20

📌 说明：

  • 对象并不是作用域（scope），所以这里==没有闭包==。
  • 对象中的函数，调用时 this 指向调用者，即对象本身。

# 传递参数为对象的 this 指向问题

在小程序或其他框架中，常见写法是传递一个对象作为参数，例如 Page({})。

js 
Page({
  data: {
    message: "Hello WeChat Mini Program"
  },
    
  handleClick() {
    this.setData({
      message: "你点击了按钮"
    });
  }
})

这里的 handleClick 被调用时，本质是 pageInstance.handleClick()，所以 this 依然指向该对象实例。

这样做的好处：

  • 避免参数过多时记忆顺序困难。
  • 统一将方法挂载到对象上，方便维护。

# 微信小程序中的闭包

在小程序中经常会看到：

js 
const that = this;

这是为了应对 回调函数中的 this 指向丢失问题。

来看一个例子：

js 
Page({
  data: {
    message: "原始数据"
  },

  onLoad() {
    const that = this; // 👈 保存 this

    wx.request({
      url: 'https://example.com/api/data',
      success: function (res) {
        // 使用 that 替代 this
        that.setData({
          message: res.data
        })
      }
    })
  }
})

这里 success 是一个回调函数，它被 wx.request 调用，而不是 Page 对象调用， 因此 success 函数的 this 指向的是 wx.request。

  • 如果直接用 this，它指向的是 wx.request 的执行环境。
  • 使用 const that = this，将外部作用域的 this 存储下来，内部函数依然可以访问 —— 这就是闭包的体现。

# 如果不使用闭包会怎样？

js 
Page({
  data: {
    message: "原始数据"
  },

  onLoad() {
    wx.request({
      url: 'https://example.com/api/data',
      success: function (res) {
        // ⚠ this 已经不是 Page
        this.setData({
          message: res.data
        })
      }
    })
  }
})

结果：

js 
TypeError: this.setData is not a function

这是因为 this 已经丢失。

# 解决方法

  1. 闭包方式
js 
const that = this;
  1. 箭头函数方式（推荐）
js 
wx.request({
  success: (res) => {
    this.setData({
      message: res.data
    })
  }
})

箭头函数不会改变 this，它继承外层作用域的 this。

# 补充：js 的 scope chain

理解闭包之前，需要理解 作用域链（scope chain）。

  • JavaScript 中的作用域由==函数==形成，而不是对象或 {}。
  • 每个函数在定义时，都会记住它所处的作用域链。
  • 当函数被调用时，会优先在自身作用域查找变量，如果找不到就向上级作用域查找，直到全局。

📌 关键点：

  • 对象不是作用域 → 对象中的函数并不会天然形成闭包。
  • 闭包的本质 → 内部函数访问了外部函数的变量，即便外部函数执行结束，该变量依然被保存下来。

# 总结

  1. 对象中的函数：谁调用指向谁，并没有闭包。
  2. 参数为对象的 this：小程序 Page 传递对象时，方法依然指向该对象。
  3. 回调函数中的 this：会丢失，需要使用闭包 const that = this 或箭头函数解决。
  4. 作用域链与闭包：闭包是函数作用域链的体现，{} 不是作用域。
