# Markdown 博客中的图床实践方案

基于 AList、PicList 和 Typora 的 Markdown 博客图床方案

# 背景说明

当前博客部署在个人云服务器上，同时使用 AList 作为存储管理工具，将服务器磁盘空间作为图床使用

现有资源：

  • 服务器存储空间约 60G
  • 支持本地存储（后续可扩展至网盘或对象存储）

这种方式的优势在于：

  • 数据完全可控
  • 成本低
  • 可扩展性强（后续可接入网盘或 CDN）

# 工具说明

整个图床方案由以下三部分组成：

# AList

作为底层存储管理工具，负责：

  • 管理服务器本地文件
  • 提供文件访问 URL
  • 支持多存储扩展（网盘、对象存储等）

在本方案中，AList 承担“图床后端”的角色

# PicList

作为上传工具，负责：

  • 接收图片（剪贴板 / 本地文件）
  • 自动上传到 AList
  • 返回图片访问 URL

它是连接编辑器与图床之间的桥梁

# Typora

作为 Markdown 编辑器，负责：

  • 编写博客内容
  • 自动调用 PicList 上传图片
  • 将图片 URL 自动插入文章中

# 整体流程

在所有工具配置完成后，博客编写流程可以简化为：

text 
编写文章 → 插入图片 → 自动上传 → 自动生成 URL → 完成

具体过程如下：

# 编写博客

在 Typora 中进行 Markdown 内容编写，保持正常写作习惯即可

# 插入图片

当插入图片（拖拽或粘贴）时：

  • Typora 会自动调用 PicList
  • PicList 将图片上传至 AList

这一过程对用户是无感的，不需要手动操作

# 图片上传与管理

图片上传后：

  • 实际存储在服务器目录（如 /data/blog-media）
  • 由 AList 统一管理
  • 自动生成可访问的 URL

例如：

text 
http://你的域名/blog-images/xxx.png

# 图片自动嵌入文章

PicList 返回的 URL 会被 Typora 自动写入 Markdown：

markdown 
![示例图片](http://你的域名/blog-images/xxx.png)

至此，图片已经完成上传、存储和引用，无需额外处理

# 方案优势

# 数据完全可控

图片存储在个人服务器中：

  • 不依赖第三方图床
  • 不存在失效风险
  • 可随时迁移

# 易于扩展

当本地存储不足时，可以无缝扩展：

  • 挂载网盘（如 OneDrive、阿里云盘）
  • 接入对象存储（S3 等）
  • 配合 CDN 提升访问速度

# 适合长期维护

该方案结构清晰，适合长期博客积累：

  • 图片路径统一
  • 便于备份
  • 易于管理

# 后续优化方向

在当前方案基础上，可以进一步优化：

# 图片优化

  • 自动压缩图片
  • 转换为 WebP 或 AVIF 格式
  • 生成缩略图

# 访问加速

通过反向代理或 CDN 提升访问速度：

  • 使用 Nginx 做反向代理
  • 接入 CDN（如 Cloudflare）

# 结构优化

统一图片目录结构，例如：

text 
/blog-images/2026/03/xxx.png

便于分类与管理

# 总结

通过 AList、PicList 与 Typora 的组合，可以构建一套完整的个人图床解决方案，实现：

  • 图片自动上传
  • 自动生成访问链接
  • 博客无缝集成

这套方案不仅适用于个人博客，也可以扩展为更完整的媒体资源管理系统，为后续画廊、视频展示等功能打下基础
