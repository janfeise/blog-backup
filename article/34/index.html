状态机

阅读时间约 43 分钟 · 字数 8403

在guess-agent中遇到了问题：需根据状态进行处理，除了绘制状态机的图外，那么<u>程序如何实现状态机呢</u>？if else？

在查看文档：https://www.runoob.com/w3cnote/verilog-fsm.html，后对状态机的实现进行梳理

有限状态机（Finite-State Machine，FSM），简称状态机，是表示有限个状态以及在这些状态之间的转移和动作等行为的数学模型

状态机可分为两类：

  • Mealy状态机：下一个状态输出，取决于当前输入和当前状态（常用的是这个）
  • Moore状态机：下一个状态输出，只取决于当前状态，与当前输入无关

文档中举例了：自动售卖机的状态机实现

背景：饮料单价 2 元，该售卖机只能接受 0.5 元、1 元的硬币。考虑找零和出货

coin = 1 代表投入了 0.5 元硬币，coin = 2 代表投入了 1 元硬币

IDLE：表示等待投币

GET N：表示已投币金额，如：GET05，表示已投0.5元

状态图分析：

饮料单价 2 元，根据投币金额决定是否出货，是否找零

从 IDLE（等待投币） 出发，coin = 1，表示投币0.5，进入GET0.5状态，再次投入coin = 1时，总投币1元，进入GET10状态，再次投入 coin = 1，总投币1.5元，进入GET15，再次投入coin = 1，总投币2元！出货，数量1瓶，不找零

若处在GET15状态，表示已投币1.5元，此时若投币 coin = 2，表示投币1元，总投币2.5元，出货！数量1瓶，找零0.5元

其它流程大致也是如此分析，不在赘述

# 状态机设计：3 段式（推荐）

状态图绘制完成后，进入最关心的程序实现部分，文档中提出，推荐使用3段式实现状态机，分为三个部分：

将当前状态和输入进行拆分

  • 状态存储
  • 状态转移逻辑
  • 输出动作

对职责进行划分，每段只处理所需逻辑

# 第一段：状态记录

在自动售卖机中存在以下几种状态：图中的4个圈圈

java 
enum 机器状态 { 空闲, 已投5角, 已投1元, 已投1元5角 }

enum 硬币 {
    五角(1),
    一元(2);
}

private 机器状态 当前状态;

public 自动售卖机() {
    this.当前状态 = 机器状态.空闲;
}

这一部分只负责“记录当前状态”，不涉及任何业务逻辑

# 第二段：下一个状态

状态转移只关心一件事：下一步去哪

java 
// ==================== 第二段：状态转移逻辑 ====================
private 机器状态 计算下一状态(机器状态 当前状态, 硬币 投入硬币) {
    switch (当前状态) {
        case 空闲:
            if (投入硬币 == 硬币.五角) return 机器状态.已投5角;
            if (投入硬币 == 硬币.一元) return 机器状态.已投1元;
            break;

        case 已投5角:
            if (投入硬币 == 硬币.五角) return 机器状态.已投1元;
            if (投入硬币 == 硬币.一元) return 机器状态.已投1元5角;
            break;

        case 已投1元:
            if (投入硬币 == 硬币.五角) return 机器状态.已投1元5角;
            if (投入硬币 == 硬币.一元) return 机器状态.空闲; // 满2元，回到空闲
            break;

        case 已投1元5角:
            // 无论投五角还是一元，都会达到或超过2元，回到空闲
            if (投入硬币 == 硬币.五角 || 投入硬币 == 硬币.一元)
                return 机器状态.空闲;
            break;
    }
    // 非法输入，保持原状态
    return 当前状态;
}

这一层完全不关心“出货”或“找零”，只处理状态变化

# 第三段：Action

action只关心行为，不关心状态如何变化，只考虑系统需要做出的行为（如：出货不找零）

java 
// ==================== 第三段：输出逻辑 ====================
private 售卖结果 执行输出(机器状态 当前状态, 硬币 投入硬币) {
    // 情况1：已投1元5角 + 投五角 = 正好2元，出货不找零
    if (当前状态 == 机器状态.已投1元5角 && 投入硬币 == 硬币.五角) {
        return 创建结果(true, false);
    }
    // 情况2：已投1元 + 投一元 = 正好2元，出货不找零
    if (当前状态 == 机器状态.已投1元 && 投入硬币 == 硬币.一元) {
        return 创建结果(true, false);
    }
    // 情况3：已投1元5角 + 投一元 = 2.5元，出货并找零0.5元
    if (当前状态 == 机器状态.已投1元5角 && 投入硬币 == 硬币.一元) {
        return 创建结果(true, true);
    }
    // 其余情况：不出货不找零
    return 创建结果(false, false);
}

这一层可以独立修改，如：后续新增“优惠活动”，只需要改这里

# 统一入口

最后，通过一个统一入口把三部分串起来

java 
/**
 * 对外唯一入口：投币
 */
public 售卖结果 投币(硬币 投入硬币) {
    // 第二段：计算下一状态
    机器状态 下一状态 = 计算下一状态(当前状态, 投入硬币);
    // 第三段：执行输出动作
    售卖结果 结果 = 执行输出(当前状态, 投入硬币);
    // 更新状态（相当于第一段非阻塞赋值）
    当前状态 = 下一状态;
    return 结果;
}

这段代码非常关键，它体现了状态机的执行顺序：

  1. 基于当前状态和输入，计算下一状态
  2. 基于当前状态和输入，产生输出
  3. 更新状态

这与硬件中的“时钟驱动”思想高度一致

以“已投 1.5 元，再投 0.5 元”为例：

# js实现自动售卖机的状态机

编写后感悟：

  1. 看图写代码：根据状态图编写每一段的代码

    • 第一段——状态：对应图中“节点”。先明确系统有哪些状态，如：空闲、已投0.5元、已投1元、已投1.5元
    • 第二段——转移：对应图中“边”。描述从当前状态在某个输入下如何走到下一个状态
    • 第三段——输出：对应图中“动作”。并非每次状态变化都有输出，只有特定路径才触发行为。以自动售卖机为例，仅三种情况产生输出：
      • 已投1.5元 + 0.5元 → 出货，不找零
      • 已投1.5元 + 1元 → 出货，找零
      • 已投1元 + 1元 → 出货，不找零 其余均为中间过程，无任何输出。

  2. 内部封闭：三段式状态机的每段都是内部实现，对外不可见

  3. 统一入口：对外只暴露一个方法。调用者无需关心当前状态、如何转移、输出如何计算——输入一个行为，得到一个结果即可

  4. 结果封装：输出通常需要封装为结构化结果返回

js 
console.log("======自动售卖机状态机正在运行中======");

// 定义状态机
class VendingMachine {
  // 第一段
  static STATES = {
    IDLE: "IDLE", // 空闲状态
    GOT05: "GOT05", // 已投入5角钱
    GOT10: "GOT10", // 已投入1元钱
    GOT15: "GOT15", // 已投入1.5元钱
  };

  static COIN = {
    con05: 0.5, // 5角钱
    con10: 1.0, // 1元钱
  };

  #currentState; // 当前状态，为私有属性

  constructor() {
    this.#currentState = VendingMachine.STATES.IDLE; // 初始状态为空闲
  }

  getCurrentState() {
    return this.#currentState;
  }

  // 第二段：状态逻辑转移，只关心下一个状态
  #nextState(coin) {
    switch (this.#currentState) {
      case VendingMachine.STATES.IDLE:
        // 空闲
        if (coin === VendingMachine.COIN.con05) {
          return VendingMachine.STATES.GOT05; // 投入5角钱
        } else if (coin === VendingMachine.COIN.con10) {
          return VendingMachine.STATES.GOT10; // 投入1元钱
        }
        break;

      case VendingMachine.STATES.GOT05:
        // 已投入5角钱
        if (coin === VendingMachine.COIN.con05) {
          return VendingMachine.STATES.GOT10; // 再投入5角钱，达到1元钱
        } else if (coin === VendingMachine.COIN.con10) {
          return VendingMachine.STATES.GOT15; // 投入1元钱，达到1.5元钱
        }
        break;

      case VendingMachine.STATES.GOT10:
        // 已投入1元钱
        if (coin === VendingMachine.COIN.con05) {
          return VendingMachine.STATES.GOT15; // 投入5角钱，达到1.5元钱
        } else if (coin === VendingMachine.COIN.con10) {
          return VendingMachine.STATES.IDLE; // 再投入1元钱，达到2元钱，出货！
        }
        break;

      case VendingMachine.STATES.GOT15:
        // 已投入1.5元钱
        if (
          coin === VendingMachine.COIN.con05 ||
          coin === VendingMachine.COIN.con10
        ) {
          return VendingMachine.STATES.IDLE; // 再投入任意硬币，达到2元钱，出货！
        }
        break;

      default:
        // 非法输入，保持当前状态
        console.error("非法输入的硬币");
        return this.getCurrentState();
    }
  }

  // 第三段：逻辑处理
  #process(coin) {
    // 情景一：已投1.5，再投5角钱，达到2元钱，出货不找零！
    if (
      this.getCurrentState() === VendingMachine.STATES.GOT15 &&
      coin === VendingMachine.COIN.con05
    ) {
      return { dispense: true, change: false };
    }
    // 情景二：已投1.5，再投1元钱，达到2.5元钱，出货并找回5角钱
    if (
      this.getCurrentState() === VendingMachine.STATES.GOT15 &&
      coin === VendingMachine.COIN.con10
    ) {
      return { dispense: true, change: true };
    }
    // 情景三：已投1元，再投1元钱，达到2元钱，出货不找零！
    if (
      this.getCurrentState() === VendingMachine.STATES.GOT10 &&
      coin === VendingMachine.COIN.con10
    ) {
      return { dispense: true, change: false };
    }

    // 其他情况，不出货，不找零
    return { dispense: false, change: false };
  }

  // 统一入口：投币
  insertCoin(coin) {
    const prevState = this.#currentState; // 当前状态

    // 先计算输出（基于当前状态和投入硬币）
    const { dispense, change } = this.#process(coin);

    // 下一个状态
    this.#currentState = this.#nextState(coin);

    // 打印结果
    console.log(
      `[${prevState}] 投入 ${coin}元 -> [${this.#currentState}] ` +
        (dispense
          ? change
            ? "🍺 出货 + 找零0.5元"
            : "🍺 出货"
          : "等待继续投币"),
    );

    return { dispense, change };
  }
}

// 情景一：已投1.5，再投5角钱，达到2元钱，出货不找零！
const vendingMachine = new VendingMachine();
vendingMachine.insertCoin(VendingMachine.COIN.con05); // 投入5角钱
vendingMachine.insertCoin(VendingMachine.COIN.con10); // 投入1元钱
vendingMachine.insertCoin(VendingMachine.COIN.con10); // 再投入1元钱，达到2元钱，出货不找零！

// 情景二：投入0.5，投入1元钱，再投1元钱，达到2.5元钱，出货并找回5角钱
const vendingMachine2 = new VendingMachine();
console.log(
  "\n======情景二：投入0.5，投入1元钱，再投1元钱，达到2.5元钱，出货并找回5角钱======",
);
vendingMachine2.insertCoin(VendingMachine.COIN.con05); // 投入5角钱
vendingMachine2.insertCoin(VendingMachine.COIN.con10); // 投入1元钱
vendingMachine2.insertCoin(VendingMachine.COIN.con10); // 再投入1元钱，达到2.5元钱，出货并找回5角钱！

# 总结

程序通过三段式实现状态机

  1. 看图写代码：根据状态图编写每一段的代码

    • 第一段——状态：对应图中“节点”。先明确系统有哪些状态，如：空闲、已投0.5元、已投1元、已投1.5元
    • 第二段——转移：对应图中“边”。描述从当前状态在某个输入下如何走到下一个状态
    • 第三段——输出：对应图中“动作”。并非每次状态变化都有输出，只有特定路径才触发行为。以自动售卖机为例，仅三种情况产生输出：
      • 已投1.5元 + 0.5元 → 出货，不找零
      • 已投1.5元 + 1元 → 出货，找零
      • 已投1元 + 1元 → 出货，不找零 其余均为中间过程，无任何输出。

  2. 内部封闭：三段式状态机的每段都是内部实现，对外不可见

  3. <u>统一入口</u>：对外只暴露一个方法。调用者无需关心当前状态、如何转移、输出如何计算——输入一个行为，得到一个结果即可

  4. 结果封装：输出通常需要封装为结构化结果返回

因此，总共有 5 段代码：

  1. 三段式状态机
  2. 统一入口
  3. 结果封装
