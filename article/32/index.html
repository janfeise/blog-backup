transition appear 在 Ctrl + F5 等强制刷新场景下失效的原因与解决方案

阅读时间约 17 分钟 · 字数 3333

浏览器渲染文档：https://developer.mozilla.org/zh-CN/docs/Web/Performance/Guides/How_browsers_work

在 Vue 中，为元素添加入场与离场动画通常通过 Transition 组件完成。当需要在首次渲染时也触发动画，可以使用 appear 属性：

vue 
<Transition appear>
  <div class="box">Hello</div>
</Transition>

在正常刷新或组件切换时，这段代码可以正常触发入场动画。但当使用 Ctrl + F5 强制刷新 时，你可能会发现：入场动画消失了，元素直接以最终状态呈现。这并不是 Vue 的 bug，而是浏览器渲染时机与资源加载机制共同作用的结果。

# 问题产生的根本原因

要理解这个问题，需要先明确浏览器的加载流程：

text 
HTML 解析 → CSS 下载 → 首次绘制（First Paint）→ JS 下载执行 → Vue 挂载

在普通刷新时：

  • 浏览器通常会使用缓存
  • JS 加载较快
  • Vue 能够在首次绘制前或紧接着完成挂载
  • Transition 能及时添加 *-enter-from 类名，从而触发动画

但在 Ctrl + F5 强制刷新 时：

  • 浏览器不使用缓存
  • JS 文件需要重新下载
  • Vue 的 mount() 执行明显延后

结果就是：

text 
浏览器已经完成首次绘制（元素已显示）
↓
Vue 才开始执行并添加 transition 类名
↓
浏览器错过动画初始帧
↓
直接呈现最终状态（动画看起来“失效”）

这就是为什么 appear 在强制刷新下表现不稳定。

# Vue Transition 的局限性

Vue 的 Transition 本质上是：

  • 在特定时机给元素添加 class
  • 依赖浏览器触发 CSS transition

例如：

css 
.fade-enter-from {
  opacity: 0;
}

.fade-enter-to {
  opacity: 1;
}

问题在于：

👉 这些 class 是“运行时添加”的

一旦添加时机晚于浏览器首次绘制，就会错过动画的起点。

# 解决思路：让动画脱离 Vue 生命周期

要彻底解决这个问题，需要引入一个关键思路：

👉 入场动画不依赖 Vue，而交给 CSS 自己执行

原因很简单：

  • CSS 在样式加载后立即生效
  • 不依赖 JS 执行
  • 不受 Vue 挂载时机影响

# 推荐方案：CSS Keyframes 接管入场，Transition 负责离场

# 实现思路

  • 入场动画：使用 CSS animation
  • 离场动画：继续使用 Vue Transition

这样可以兼顾：

  • 强制刷新下的稳定入场动画
  • Vue 控制的灵活离场动画

# Demo

# 组件代码

vue 
<script setup>
import { ref } from 'vue'

const visible = ref(true)

function toggle() {
  visible.value = !visible.value
}
</script>

<template>
  <button @click="toggle">切换</button>

  <Transition name="slide">
    <div v-if="visible" class="box">
      内容区域
    </div>
  </Transition>
</template>

# 样式代码

css 
.box {
  width: 200px;
  height: 100px;
  background: skyblue;
  margin-top: 20px;

  /* 入场动画：由 CSS 接管 */
  animation: slideIn 0.6s ease;
}

/* 入场关键帧 */
@keyframes slideIn {
  from {
    transform: translateY(-30px);
    opacity: 0;
  }
  to {
    transform: translateY(0);
    opacity: 1;
  }
}

/* 离场动画：由 Vue Transition 控制 */
.slide-leave-active {
  transition: all 0.4s ease;
}

.slide-leave-from {
  opacity: 1;
  transform: translateY(0);
}

.slide-leave-to {
  opacity: 0;
  transform: translateY(-30px);
}

# 关键细节说明

# 为什么这样可以解决问题

  • animation 在 CSS 加载完成后立即生效
  • 不依赖 Vue 的 mount
  • 即使 JS 很慢，动画仍然能正常执行

# 关于 forwards 的坑

在入场动画中需要特别注意：

css 
animation: slideIn 0.6s forwards;

forwards 会导致：

text 
动画结束后，最终状态被“锁死”

这会带来一个问题：

👉 后续 Vue 的 Transition 无法再修改 transform 或 opacity

例如离场动画：

css 
.slide-leave-to {
  transform: translateY(-100%);
}

可能不会生效，因为：

text 
animation 的最终样式优先级更高

# 更安全的写法

避免使用 forwards，或者在动画结束后释放控制权：

css 
animation: slideIn 0.6s;

# 方案总结

在涉及首屏或强制刷新场景时：

  • Transition appear 并不可靠
  • 问题根源是 JS 执行晚于浏览器首次绘制
  • Vue 无法保证动画的起始帧被正确捕捉

更稳妥的方案是：

text 
入场动画 → CSS Keyframes（脱离 Vue）
离场动画 → Vue Transition（可控）

这种组合方式既保证了动画的稳定性，又保留了 Vue 的灵活性。

# 结语

当动画依赖运行时逻辑时，就必须考虑执行时机的不确定性。强制刷新只是放大了这一问题。在实际项目中，涉及首屏或关键视觉效果时，优先选择不依赖 JS 的方案，往往能获得更稳定的用户体验
