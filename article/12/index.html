# Spring Boot 接口开发

本文以"创建文章"这一个接口为例，详细说明 Spring Boot 接口开发的完整流程，从数据库到前端的每一步操作

# 流程图

text 
Entity (实体层) → DAO (数据访问层) → Service (业务层) → Controller (控制器层)
                      ↓
                 Mapper XML (SQL映射)

# 第一步：准备 Entity 实体类

实体类对应数据库表，使用 Lombok 简化代码。

java 
@Data
@Entity
@Table(name = "posts")
public class Post {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;
    
    private String title;
    
    @Column(columnDefinition = "TEXT")
    private String content;
    
    private String status;
    
    @Column(name = "created_at")
    private LocalDateTime createdAt;
    
    @Column(name = "updated_at")
    private LocalDateTime updatedAt;
}

# 第二步：创建 DAO 接口

在 dao 包下创建数据访问接口。

java 
@Mapper
public interface PostDao {
    /**
     * 插入文章
     */
    int insert(Post post);
}

# 第三步：编写 Mapper XML

在 resources/mappers/PostMapper.xml 中实现 SQL。

xml 
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" 
    "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="com.example.dao.PostDao">
    <!-- 插入文章 -->
    <insert id="insert" useGeneratedKeys="true" keyProperty="id">
        INSERT INTO posts (title, content, status, created_at, updated_at)
        VALUES (#{title}, #{content}, #{status}, #{createdAt}, #{updatedAt})
    </insert>
</mapper>

关键配置：

  • useGeneratedKeys="true"：自动获取数据库生成的主键
  • keyProperty="id"：将主键值回填到 Post 对象的 id 属性

# 第四步：编写单元测试

在正式开发业务逻辑前，先测试 DAO 层是否正常工作。

# 第五步：创建 DTO 和 VO

# DTO - 接收前端数据

java 
/**
 * 上传文章的 DTO
 * DTO (Data Transfer Object): 前端 → 后端的数据传输对象
 */
@Data
public class UploadArticleDTO {
    
    @NotBlank(message = "标题不能为空")
    @Size(max = 200, message = "标题长度不能超过200字符")
    private String title;

    @NotBlank(message = "内容不能为空")
    private String content;

    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
    private LocalDateTime createdAt;
}

# VO - 返回给前端的数据

java 
/**
 * 文章视图对象
 * VO (View Object): 后端 → 前端的数据展示对象
 */
@Data
public class ArticleVO {
    private Integer id;
    private String title;
    private String content;
    private String status;
    
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
    private LocalDateTime createdAt;
    
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
    private LocalDateTime updatedAt;
}

为什么要区分 DTO 和 VO？

  • DTO：用于数据校验，可能只包含部分字段
  • VO：用于数据展示，可能包含额外的计算字段或关联数据
  • 解耦前后端数据结构，互不影响

# 第六步：编写 Service 业务层

# 定义接口

java 
public interface ArticleService {
    /**
     * 创建文章
     */
    ArticleVO createArticle(UploadArticleDTO dto);
}

# 实现业务逻辑

在 service/impl 包下实现：

java 
@Service
@Slf4j
public class ArticleServiceImpl implements ArticleService {
    
    @Autowired
    private PostDao postDao;
    
    /**
     * 创建文章
     * 
     * 业务逻辑：
     * 1. DTO → Entity 转换
     * 2. 设置默认值（status、时间戳）
     * 3. 调用 DAO 插入数据库
     * 4. Entity → VO 转换并返回
     */
    @Override
    @Transactional
    public ArticleVO createArticle(UploadArticleDTO dto) {
        log.info("开始创建文章: {}", dto);
        
        // 1. DTO → Entity 转换
        Post post = new Post();
        BeanUtils.copyProperties(dto, post);
        
        // 2. 设置默认值
        post.setStatus("draft");  // 默认为草稿状态
        
        LocalDateTime now = LocalDateTime.now();
        if (post.getCreatedAt() == null) {
            post.setCreatedAt(now);
        }
        post.setUpdatedAt(now);
        
        // 3. 插入数据库
        postDao.insert(post);
        
        log.info("文章创建成功，ID: {}", post.getId());
        
        // 4. Entity → VO 转换
        ArticleVO vo = new ArticleVO();
        BeanUtils.copyProperties(post, vo);
        
        return vo;
    }
}

关键点：

  • @Transactional：开启事务，保证数据一致性
  • BeanUtils.copyProperties()：快速复制对象属性
  • 业务逻辑在 Service 层处理，不在 Controller 层

# 第七步：编写 Controller 控制器

java 
/**
 * 文章控制器
 */
@RestController
@RequestMapping("/articles")
@Slf4j
public class ArticleController {
    
    @Autowired
    private ArticleService articleService;

    /**
     * 创建文章
     * POST /articles
     * 
     * 前端调用示例：
     * fetch('/articles', {
     *   method: 'POST',
     *   headers: { 'Content-Type': 'application/json' },
     *   body: JSON.stringify({
     *     title: '我的第一篇文章',
     *     content: '这是文章内容'
     *   })
     * })
     */
    @PostMapping
    public ResultMsg<ArticleVO> createArticle(
            @RequestBody @Validated UploadArticleDTO dto) {
        log.info("收到创建文章请求: {}", dto);

        ArticleVO savedArticle = articleService.createArticle(dto);
        
        return ResultMsg.success(savedArticle);
    }
}

注解说明：

  • @RestController：标识为 REST 控制器，自动返回 JSON
  • @RequestMapping：定义基础路径
  • @PostMapping：处理 POST 请求
  • @RequestBody：接收 JSON 格式的请求体
  • @Validated：启用参数校验

# 第八步：配置统一响应格式

java 
/**
 * 统一响应结果
 */
@Data
@AllArgsConstructor
public class ResultMsg<T> {
    private Integer code;
    private String message;
    private T data;
    
    public static <T> ResultMsg<T> success(T data) {
        return new ResultMsg<>(200, "success", data);
    }
    
    public static <T> ResultMsg<T> error(String message) {
        return new ResultMsg<>(500, message, null);
    }
}

# 第九步：配置全局异常处理

java 
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {
    
    /**
     * 处理参数校验异常
     */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResultMsg<Void> handleValidationException(
            MethodArgumentNotValidException e) {
        String message = e.getBindingResult()
                .getFieldError()
                .getDefaultMessage();
        log.error("参数校验失败: {}", message);
        return ResultMsg.error(message);
    }
}

# 完整流程总结

步骤 层级 职责 关键操作
1 Entity 数据库映射 定义表结构
2 DAO 数据访问 定义方法签名
3 Mapper XML SQL 实现 编写 SQL 语句
4 Test 单元测试 验证 DAO 功能
5 DTO/VO 数据传输 定义前后端数据格式
6 Service 业务逻辑 DTO→Entity→VO 转换
7 Controller 接口暴露 接收请求，返回响应
8 ResultMsg 统一响应 封装返回格式
9 Exception 异常处理 统一错误处理

# 📌 核心要点

  1. 分层清晰：Controller → Service → DAO，各层职责明确
  2. 数据转换：DTO（入参） → Entity（数据库） → VO（出参）
  3. 参数校验：在 DTO 中使用注解校验，Controller 启用 @Validated
  4. 事务管理：Service 层写操作添加 @Transactional
  5. 主键回填：MyBatis 配置 useGeneratedKeys="true"
  6. 异常处理：全局异常处理器统一处理错误
