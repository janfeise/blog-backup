Ant-Design-Vue Image-Preview 组件箭头图标局部替换

2026.08.08 发布 62 分钟阅读 更新于 2026.10.02

在实习时，UI 的设计稿将 antdv 的 image-preview 组件的左右箭头替换为 UI 所设计的icon，尝试了多次后才成功替换，在此做一个记录

# 需求

  1. icon替换：将 a-image-preview-group 的默认左右箭头替换为自定义图标，并分别提供 normal、hover、click 三种状态的icon

  2. 局部替换，不影响全局：同时要求本次修改只作用于当前 a-image-preview-group，不能影响项目中其他页面的图片预览组件

# 踩坑记录

# preview.rootClassName 没有生效

最开始让 deepseek-v4 pro 更改，尝试通过 preview.rootClassName 给当前图片预览面板添加独立类名

vue 
<a-image-preview-group
    :preview="{
        rootClassName: 'facility-image-preview'
    }"
>
    ...
</a-image-preview-group>

然后通过该类名限制箭头样式的作用范围

scss 
.facility-image-preview {
    .ant-image-preview-switch-left {
        ...
    }
}

但实际测试发现，antdv 根本没有提供 rootClassName 的api，纯 AI 幻觉

https://antdv.com/components/image-cn#api

后续发现 Ant Design Vue 4.x 的 PreviewGroup 封装层会覆盖用户传入的 rootClassName，并使用组件内部生成的 hashId

js 
// node_modules/ant-design-vue/es/image/PreviewGroup.js

const _preview = typeof preview === 'object' ? preview : {}

return _extends(_extends({}, _preview), {
    rootClassName: hashId.value
})

这里先展开用户传入的 _preview，然后再次设置 rootClassName

因此，用户传入的：

js 
rootClassName: 'facility-image-preview'

最终会被hashId 覆盖：

js 
rootClassName: hashId.value

所以不能依赖 preview.rootClassName 实现当前预览组件的样式隔离

# scoped CSS 无法命中预览面板

另一种尝试是在当前 Vue 组件的 scoped 样式中直接修改箭头

vue 
<style lang="scss" scoped>
:deep(.ant-image-preview-switch-left) {
    ...
}
</style>

但图片预览面板默认通过 Portal 挂载到 document.body，并不在当前 Vue 组件的 DOM 树中

Vue 的 scoped 样式会被编译为带有 data-v-xxx 属性的选择器

css 
[data-v-xxx] .ant-image-preview-switch-left {
    ...
}

而预览面板位于 document.body 下，不属于当前带有 data-v-xxx 的组件节点，因此选择器无法命中

即使使用 :deep()，也无法改变预览面板已经脱离当前组件 DOM 树这一事实

# 全局选择器会影响其他组件

如果直接使用全局选择器，样式可以正常生效

scss 
.ant-image-preview-switch-left {
    ...
}

.ant-image-preview-switch-right {
    ...
}

但这种方式会修改项目中所有 a-image-preview-group 的左右箭头，其他页面中的 ImageViewer.vue 也会被影响

因此，全局选择器虽然可行，但不满足本次需求中的局部作用域要求

# 解决方案

最终采用 getContainer + ref + 后代选择器 实现局部替换

整体思路分为两步：

  • 通过 ref 获取当前组件的容器节点

  • 通过后代选择器，只修改该容器内部的图片预览箭头

# 通过 ref 指定预览面板的挂载位置

首先，在当前组件的根容器上绑定 rootRef

vue 
<template>
    <div
        ref="rootRef"
        class="pr-10 scroll-container"
    >
        <a-image-preview-group
            :preview="{
                getContainer: () => rootRef,
                onVisibleChange: onPrevVisibleChange
            }"
        >
            <a-image
                v-for="item in imgList"
                :key="item.uid"
                :src="item.url"
            />
        </a-image-preview-group>
    </div>
</template>

在脚本中声明对应的模板引用

js 
import { ref } from 'vue'

const rootRef = ref(null)

在 Vue 模板表达式中，ref 会被自动解包，因此：

js 
getContainer: () => rootRef

实际返回的是 rootRef.value 对应的 DOM 元素

Ant Design Vue 获取到该容器后，会将当前 a-image-preview-group 的预览面板挂载到 .scroll-container 内部，而不是默认挂载到 document.body

# 使用后代选择器精确替换箭头

预览面板挂载到 .scroll-container 后，最终生成的左右切换按钮会成为该容器的后代元素

此时可以通过：

scss 
.scroll-container .ant-image-preview-switch-left

精确匹配当前组件中的预览箭头

vue 
<style lang="scss">
.scroll-container {
    .ant-image-preview-switch-left,
    .ant-image-preview-switch-right {
        background: none !important;

        > .anticon {
            display: none !important;
        }

        &::before {
            content: '';
            display: block;
            width: 56px;
            height: 56px;
            background-position: center;
            background-size: contain;
            background-repeat: no-repeat;
        }
    }

    .ant-image-preview-switch-left {
        &::before {
            background-image: url('@/assets/highwayAsset/normal-left.png');
        }

        &:hover::before {
            background-image: url('@/assets/highwayAsset/hover-left.png');
        }

        &:active::before {
            background-image: url('@/assets/highwayAsset/click-left.png');
        }
    }

    .ant-image-preview-switch-right {
        &::before {
            background-image: url('@/assets/highwayAsset/normal-right.png');
        }

        &:hover::before {
            background-image: url('@/assets/highwayAsset/hover-right.png');
        }

        &:active::before {
            background-image: url('@/assets/highwayAsset/click-right.png');
        }
    }

    .ant-image-preview-switch-left-disabled,
    .ant-image-preview-switch-right-disabled {
        cursor: not-allowed;

        &::before {
            opacity: 0.6;
        }
    }
}
</style>

这部分样式不能使用普通的 scoped 写法

预览面板虽然被挂载到了 .scroll-container 内部，但预览组件生成的 DOM 元素不会自动携带当前组件的 data-v-xxx 属性

因此这里使用非 scoped 样式，再通过 .scroll-container 限定作用范围

# 样式处理说明

隐藏 Ant Design Vue 默认箭头背景：

scss 
background: none !important;

隐藏默认的 SVG 图标：

scss 
> .anticon {
    display: none !important;
}

使用伪元素承载自定义图标：

scss 
&::before {
    content: '';
    display: block;
    width: 56px;
    height: 56px;
    background-position: center;
    background-size: contain;
    background-repeat: no-repeat;
}

通过不同的伪类切换图片状态：

scss 
&::before {
    background-image: url('normal.png');
}

&:hover::before {
    background-image: url('hover.png');
}

&:active::before {
    background-image: url('click.png');
}

在第一张或最后一张图片时，Ant Design Vue 会添加 disabled 类名，此时降低自定义箭头的透明度：

scss 
.ant-image-preview-switch-left-disabled,
.ant-image-preview-switch-right-disabled {
    cursor: not-allowed;

    &::before {
        opacity: 0.6;
    }
}

# DOM 结构变化

修改前，预览面板默认挂载在 document.body 下：

html 
<body>
    <div id="app">
        <div class="scroll-container">
            <!-- 当前组件 -->
        </div>
    </div>

    <div class="ant-image-preview-root">
        <div class="ant-image-preview-switch-left">
            <span class="anticon">
                ...
            </span>
        </div>
    </div>
</body>

此时 .scroll-container 和预览箭头之间不存在父子关系，下面的选择器无法命中：

scss 
.scroll-container {
    .ant-image-preview-switch-left {
        ...
    }
}

增加 getContainer 后，预览面板被挂载到 rootRef 对应的 .scroll-container 内：

html 
<body>
    <div id="app">
        <div class="scroll-container">
            <!-- 当前组件 -->

            <div class="ant-image-preview-root">
                <div class="ant-image-preview-switch-left">
                    <span class="anticon">
                        ...
                    </span>
                </div>
            </div>
        </div>
    </div>
</body>

此时预览箭头是 .scroll-container 的后代元素，因此后代选择器能够正常命中：

scss 
.scroll-container {
    .ant-image-preview-switch-left {
        ...
    }
}

# 最终效果

状态 图标 触发方式
normal normal-left.png、normal-right.png 默认状态
hover hover-left.png、hover-right.png 鼠标悬停
click click-left.png、click-right.png 鼠标按下
disabled 自定义图标透明度降低 第一张的左箭头或最后一张的右箭头

最终方案虽然使用了非 scoped 样式，但所有规则都被限制在 .scroll-container 后代中

其他图片预览组件仍然挂载在默认容器中，不属于当前 .scroll-container，因此不会受到本次样式修改的影响

# getContainer 带来的副作用

通过 getContainer 将预览面板挂载到当前组件容器后，虽然解决了箭头样式只能局部生效的问题，但也引入了一个新的生命周期问题

# 问题现象

存在详情态和编辑态两种状态，详情态可全屏预览图片，并通过 getContainer 将全屏预览的上/下切换箭头进行了替换，但却产生了新的问题：

text 
详情态点击图片全屏预览
    ↓
关闭图片预览
    ↓
点击“编辑”按钮
    ↓
页面白屏，编辑态内容完全不可见

这里的“白屏”并不一定表示编辑态内容没有渲染，更可能是图片预览遗留的遮罩层仍然覆盖在编辑内容上方

# 再次踩坑

最初判断是 v-if / v-else 切换时，a-image-preview-group 销毁过快，而 Preview Dialog 的关闭和清理还没有完成

围绕这个方向尝试了两种方案

# 将 Preview 改为受控模式

通过变量控制预览状态，并在进入编辑态前主动关闭预览

js 
const previewOpen = ref(false)

function enterEdit() {
    previewOpen.value = false
    isEdit.value = true
}

但实际测试后问题仍然存在

即使 visible 已经变为 false，Dialog 的关闭动画和 Portal DOM 清理仍然是异步进行的

# 使用 nextTick 延迟切换编辑态

尝试先关闭预览，再等待 Vue 完成本轮 DOM 更新，最后进入编辑态

js 
async function enterEdit() {
    previewOpen.value = false

    await nextTick()

    isEdit.value = true
}

该方式同样没有解决问题

nextTick 只能等待 Vue 当前批次的 DOM 更新完成，无法等待 Ant Design Vue Dialog 的关闭动画和异步卸载完成

# 根因

之前为了限制箭头样式的作用范围，使用了：

vue 
<a-image-preview-group
    :preview="{
        getContainer: () => rootRef,
        onVisibleChange: onPrevVisibleChange
    }"
>

其中 rootRef 对应当前组件的 .scroll-container

vue 
<div
    ref="rootRef"
    class="scroll-container"
>

这意味着图片预览 Dialog 不再挂载到默认的 document.body，而是挂载到 .scroll-container 内部

DOM 结构类似：

html 
<div class="scroll-container">
    <!-- 详情态内容 -->

    <div class="ant-image-preview-root">
        <div class="ant-image-preview-mask"></div>
        <div class="ant-image-preview-wrap">
            ...
        </div>
    </div>
</div>

详情态和编辑态原本通过 v-if / v-else 切换：

vue 
<template v-if="!isEdit">
    <a-image-preview-group>
        ...
    </a-image-preview-group>
</template>

<template v-else>
    <!-- 编辑态 -->
</template>

当 isEdit 变为 true 时，Vue 会同步销毁详情态中的 a-image-preview-group

但 Ant Design Vue Dialog 的销毁并不是完全同步的，它还需要执行关闭动画，并在动画结束后清理 Portal DOM

整个过程可以理解为：

text 
isEdit 变为 true
    ↓
v-if 销毁 a-image-preview-group
    ↓
Preview Dialog 开始执行关闭动画
    ↓
同一时间，编辑态内容已经完成渲染
    ↓
Portal DOM 和遮罩层暂时仍存在于 rootRef 内
    ↓
遮罩层覆盖编辑态内容
    ↓
页面看起来像白屏

问题本质是：

text 
Vue 的 v-if 同步销毁
        与
Ant Design Vue Dialog 的异步卸载
        之间产生了生命周期竞态

v-if 不会等待 Dialog 完成关闭动画后再销毁 a-image-preview-group

而当 Dialog 被挂载到当前组件容器内部时，尚未卸载的遮罩层会直接覆盖同一容器中的编辑态内容

# 修复方案

将详情态和编辑态的 v-if / v-else 改为 v-show

修改前：

vue 
<template v-if="!isEdit">
    <a-image-preview-group
        :preview="{
            getContainer: () => rootRef,
            onVisibleChange: onPrevVisibleChange
        }"
    >
        ...
    </a-image-preview-group>
</template>

<template v-else>
    <!-- 编辑态 -->
</template>

修改后：

vue 
<div v-show="!isEdit">
    <a-empty
        v-if="!hasImg"
        description="暂无设施照片"
    />

    <a-image-preview-group
        v-else
        :preview="{
            getContainer: () => rootRef,
            onVisibleChange: onPrevVisibleChange
        }"
    >
        ...
    </a-image-preview-group>
</div>

<div v-show="isEdit">
    <!-- 编辑态 -->
</div>

需要注意，v-show 不能直接用于 <template>，因为它需要通过修改真实 DOM 元素的 display 样式控制显示和隐藏

因此需要将原来的 <template> 改为 <div> 或其他真实元素

# 为什么 v-show 可以解决

v-if 和 v-show 的核心区别在于：

指令 切换方式 组件实例
v-if 创建或销毁 DOM 会被销毁和重新创建
v-show 修改 display 始终保留

使用 v-show 后，a-image-preview-group 不会因为进入编辑态而立即销毁

text 
点击编辑
    ↓
关闭 Preview Dialog
    ↓
详情态通过 display: none 隐藏
    ↓
a-image-preview-group 实例仍然存在
    ↓
Dialog 按照自身生命周期完成关闭动画
    ↓
Portal DOM 和遮罩层正常卸载

由于组件实例仍然存活，Preview Dialog 可以完整处理 visible 变化、关闭动画和 Portal 清理，不会在卸载过程中被 v-if 强行销毁

最终避免遮罩层残留在 .scroll-container 内部，也就不会继续覆盖编辑态内容

# 修改后的结构

vue 
<template>
    <div
        ref="rootRef"
        class="scroll-container"
    >
        <!-- 详情态 -->
        <div v-show="!isEdit">
            <a-empty
                v-if="!hasImg"
                description="暂无设施照片"
            />

            <a-image-preview-group
                v-else
                :preview="{
                    getContainer: () => rootRef,
                    onVisibleChange: onPrevVisibleChange
                }"
            >
                <a-image
                    v-for="item in imgList"
                    :key="item.uid"
                    :src="item.url"
                />
            </a-image-preview-group>
        </div>

        <!-- 编辑态 -->
        <div v-show="isEdit">
            ...
        </div>
    </div>
</template>

# 总结

getContainer 将 Preview Dialog 挂载到当前组件容器后，使局部样式覆盖成为可能，但也让 Dialog 的 Portal 生命周期和当前组件的视图切换产生关联

当详情态使用 v-if 销毁时，Vue 的同步卸载可能和 Dialog 的异步关闭动画产生竞态，导致遮罩层短暂或持续覆盖编辑态内容

将详情态和编辑态改为 v-show 后，a-image-preview-group 始终保持挂载，Dialog 可以按照自身生命周期正常关闭和清理

最终方案为：

text 
getContainer + ref
    解决预览箭头的局部样式作用域

v-show
    避免 Preview Dialog 异步卸载与视图切换产生竞态
