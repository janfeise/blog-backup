# 用「守卫式 return」优化 if 判断的代码风格

# 一、常规写法的问题

在日常开发中，我们经常需要通过 if 判断某个条件是否成立，然后再执行代码。例如：

js 
function process(data) {
  if (check(data) === true) {
    console.log("数据符合条件，开始处理...");
    // 一系列复杂的逻辑
    doSomething(data);
    saveResult(data);
  }
}

这样写虽然没有问题，但随着逻辑增多，容易形成「缩进地狱」：

  • 每多一层判断，就多一层缩进。
  • 外围逻辑被包裹在条件里，阅读时不够直观。

# 二、守卫式写法：if(!check()) return

为了避免深层缩进，可以采用「守卫式 return」（Guard Clause）：

js 
function process(data) {
  // guard line
  if (!check(data)) return; 
    
  console.log("数据符合条件，开始处理...");
  doSomething(data);
  saveResult(data);
}

这里的逻辑是：

  1. 先排除不符合条件的情况。
  2. 符合条件时，自然往下执行。

这种方式可以让代码结构扁平化，逻辑一目了然。

# 三、守卫式写法的优势

  1. 减少缩进
    • 不再需要将核心逻辑放在大括号里。
    • 逻辑展开更清晰。
  2. 逻辑更直观
    • 一看函数开头，就能知道「哪些情况直接返回」。
    • 有点类似「门卫把不合格的人挡在门口，符合条件的才继续进入」。
  3. 提高可维护性
    • 当有多个条件时，可以连用多个守卫式 return，避免层层嵌套：
js 
function process(data) {
  if (!data) return;
  if (!checkType(data)) return;
  if (!hasPermission(data)) return;
  
  // 核心逻辑只保留一层
  doSomething(data);
  saveResult(data);
}

# 四、总结

在编程中，避免「缩进地狱」是写出清晰代码的重要一步。
与其写成：

js 
if (check()) {
  // 一堆逻辑
}

不如直接写成：

js 
// guard line
if (!check()) return;

// 一堆逻辑

这种「守卫式 return」的写法，能够让函数逻辑更简洁、可读性更强。
